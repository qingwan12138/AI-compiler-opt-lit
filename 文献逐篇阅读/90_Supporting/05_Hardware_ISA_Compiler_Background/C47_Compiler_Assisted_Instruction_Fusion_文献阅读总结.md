## 1. 研究背景

指令融合把若干架构指令合并为一个微操作，可减少重排序缓冲区、加载/存储队列等结构的占用。传统融合多针对相邻指令；要融合非相邻内存指令，硬件通常还需预测、验证、错误恢复和提交约束，增加复杂度。作者观察到，编译器可静态看到比处理器分配队列更大的指令窗口，因此可在生成代码时主动整理可融合的内存访问。

## 2. 论文要解决的问题

论文研究如何在不依赖昂贵的非相邻融合预测硬件的情况下，把静态可判定、原本不相邻的内存指令安全地变成相邻指令，同时确保 LLVM 中端和后端优化不会破坏顺序。

> 核心问题：如何用编译期依赖分析和后端顺序约束，将潜在的非相邻内存融合机会转化为无需推测即可执行的相邻融合。

## 3. 核心方法概述

CAIF（Compiler-Assisted Instruction Fusion）分为中端分析/重排与后端顺序保持两部分。中端在基本块内寻找地址范围可融合的 load/load 或 store/store，提取尾指令所需的 use-def 链，并用别名与内存依赖分析验证搬移安全性；满足条件后把必要计算提升到头指令前，再将尾内存操作紧跟头指令。后端通过伪指令将候选操作成对打包，并以 DAGMutation 为晚期漏网候选施加弱聚类约束，最终恢复原始标量指令但保留顺序。

```text
LLVM IR / O3
  → 基本块内候选内存操作配对与地址距离判断
  → use-def 链、别名分析、内存依赖检查
  → 安全重排并可选动态循环展开
  → 后端伪指令 + DAGMutation 保序
  → RISC-V 机器码与相邻指令融合
```

## 4. 实验框架与训练流程

论文不涉及机器学习模型训练。方法由 LLVM 中端/后端静态分析、代码变换和模拟器实验构成。

### 4.1 候选识别与正确性约束

对每个基本块扫描内存操作对，检查其基址、偏移或 Scalar Evolution 推导出的地址距离，候选必须处于可融合范围（文中以 64 字节为界）。编译器收集两条内存指令之间的 catalyst 指令，并分析尾指令所需的地址/存储值计算。别名分析检查重排是否跨越冲突的 load/store；无法证明安全时不变换。方法融合相同类型的内存操作，不把任意算术指令作为融合对。

### 4.2 后端保序

成对伪指令帮助顺序穿过 O3 优化、指令选择和寄存器分配；DAGMutation 对伪指令未覆盖的候选插入弱聚类边。调度和寄存器分配完成后再展开伪指令。动态循环展开只针对满足约束的内层循环，展开因子为 2，以扩展静态分析窗口并控制寄存器压力。

### 4.3 实验执行

PyTorch 模型经 ONNX、MLIR/LLVM 路径转为 RISC-V 64G 可执行文件；Pin 统计指令并生成 trace，修改后的 Spike 提供执行指令流，再送入周期级模拟器评估性能与能耗。

## 5. 奖励函数、损失函数或关键公式

论文不使用奖励函数或训练损失。变换成立的关键条件是：头尾内存操作地址间距满足目标融合器条件，且尾指令及其依赖链搬移后不越过冲突的内存访问；任何无法通过别名/依赖检查的候选均保守放弃。硬件侧对融合类型按复杂度区分：相邻、同基址连续地址；相邻、同基址且在 cache line 内；相邻不同基址；以及非相邻推测融合。

评估报告相对无融合基线的归一化执行时间、融合指令占比、MPKI、ROB/LQ/SQ 分配停顿和能耗。执行时间降低百分比不等于 IPC 提升百分比，笔记分别沿用论文指标口径。

## 6. 实验设置

### 6.1 工作负载

神经网络测试包括 AlexNet、ResNet、MobileNet、MLP、MNIST、NSNet2、BERT、RoBERTa 及稀疏 BERT/DistilBERT 的代表层；通用程序使用 SPEC CPU 2017 整数速度测试，并对有代表性的函数选取 ROI。

### 6.2 编译器与处理器模型

实现基于 LLVM；所有编译阶段采用 O3，目标为 RISC-V 64G。主要模拟器配置近似 Intel Gracemont 风格乱序核，另评估更大的 Golden Cove 风格核心。内存能耗以 CACTI 对 LQ、SQ、L1D 建模；Helios 配置表示支持非相邻推测融合的硬件。

### 6.3 对比组

对比 Base（标准 O3，无重排）与 CAIF；硬件从 NoFusion、仅相邻同基址融合、相邻同基址 cache-line 融合，到 Helios。消融也考察 CAIF 是否开启动态循环展开及向量化支持。

## 7. 实验结果与结论

### 7.1 融合机会

神经网络中，CAIF 把 Helios 下非相邻融合平均占比从 27.12% 降至 8.96%，相邻同基址连续融合从 1.94% 提高到 61.67%。作者报告 CAIF 本身只执行非推测相邻融合，因此不发生融合误预测。

### 7.2 执行时间

在所测神经网络上，仅具备简单相邻融合的硬件配合 CAIF，平均执行时间相对无融合 Base 降低 19.6%；Helios 从 Base 下的 6.6% 平均降低幅度增至与 CAIF 配合时的 20.3%。SPEC CPU 2017 上，相应的 CAIF 改善也高于标准编译配置；论文在摘要中分别报告不同硬件配置由 2.4% 至 6.4%、由 14.4% 至 17.7% 的提升。向量化开启后，收益缩小但仍有报告的平均提升。

### 7.3 停顿与能耗

CAIF 降低 ROB、LQ、SQ 满导致的分配停顿。作者还报告 CAIF 在多种硬件配置下减少 L1D、LQ/SQ 能耗；简单相邻融合硬件配合 CAIF 可在相近性能下少用比 Helios-Base 更复杂的硬件机制。

## 8. 主要创新点

1. 将部分非相邻融合机会在编译期转为相邻指令，减少硬件预测、验证和回滚责任。
2. 通过 use-def、别名和内存依赖分析，保守识别可安全重排的内存访问。
3. 结合中端伪指令和后端 DAGMutation，在 LLVM O3 优化、调度与寄存器分配过程中维持融合顺序。
4. 在 RISC-V 神经网络与 SPEC 工作负载上评估简单融合硬件与软件重排的协同效果。

## 9. 局限性

论文的静态变换主要限制在基本块内；跨越更广控制流和复杂动态别名的机会不一定可利用。DAGMutation 的弱依赖可能受寄存器压力影响，伪指令则可能短暂妨碍单条指令级优化，因此需要两种机制配合。实验基于 Spike trace 和周期级模型，而非商业 RISC-V 硅片；所报告收益受模拟器、工作负载和特定融合硬件模型影响。文中也指出，把短延迟头指令与长延迟尾指令配对可能延长依赖链，存在融合收益与等待时间之间的权衡。

## 10. 阅读后的研究方向反思

该工作适合作为 RISC-V 后端优化和软硬协同设计的直接参考。它揭示了一个值得实测的问题：硬件可见的指令窗口和编译器静态可见窗口并不相同，优化并非只靠增加微架构复杂度。要扩展到 RVV 或更真实的处理器，应把 ISA 约束、调度器行为、寄存器压力及真实 PMU 数据放进闭环，而不能将模拟器结果直接外推为实机收益。

## 11. 可进一步尝试的研究方向

### 11.1 RISC-V/RVV 真实硬件上的融合收益与代价验证

问题是 CAIF 的配对与重排在不同 RISC-V 核心、cache line 和访存队列设计上能否稳定获益。可在 LLVM 后端保留可开关 pass，使用 Spike 做语义回归、真实板卡 PMU/时间测量，并分离指令融合、动态展开、普通调度优化的贡献。

### 11.2 依赖长度感知的融合选择

将静态延迟估计或硬件反馈加入候选排序，避免把长延迟尾访存放到短依赖头后导致关键路径拉长；用消融评估性能、能耗和融合覆盖率的 Pareto 关系。此处是基于论文局限提出的研究设想，不是原论文已验证方案。

## 12. 与其他已读文献的关系

与 C20（从 ISA 规范综合指令选择后端）相比，C20 关注目标指令选择规则生成，CAIF 关注已选内存操作在代码流中的相对位置。与 C23（RISC-V 多层后端）及 C32（CGRA 编译）相比，CAIF 的范围更窄但连接编译调度与微架构融合机制。它与传统调度、内存别名分析文献相关；不应归为 LLM/RL 方法，因为论文没有模型参与决策。

## 13. 一页式总结

**问题：** 非相邻内存指令的动态融合需要更复杂的硬件预测与验证。

**方法：** LLVM 静态识别可融合 load/load、store/store 对；检查地址范围、use-def 和内存依赖后重排；用伪指令及 DAGMutation 穿越后端并保序。

**证据：** 在 RISC-V 64G、神经网络与 SPEC CPU 2017 的模拟评估中，CAIF 提高相邻融合比例，并降低多种配置下的执行时间、队列停顿和部分结构能耗。

**分类：** SUPPORTING / B5_Hardware_ISA_Compiler_Background；传统编译器/硬件协同优化，不属于 LLM 的 selector、translator 或 generator 角色。

**研究价值：** 对 RV64/RVV 后端优化、编译器与融合微架构的协同评估有参考价值；真实硬件验证和依赖感知决策仍值得研究。
