## 1. 研究背景

本文研究应用专用指令集处理器（Application-Specific Instruction-Set Processor，ASIP）。ASIP 在通用处理器的可编程性与 ASIC/专用加速器的性能、能效之间折中：基础处理器处理一般功能，面向目标工作负载的热点计算则由定制指令和功能单元加速（第 1 节）。

RISC-V 的开放 ISA 和软硬件生态降低了开展 ASIP 定制的门槛，但定制仍需要同时理解应用数据流、指令编码、寄存器文件、流水线、关键路径、面积和性能。已有工作通常从编译器 IR 或 DFG 中枚举候选子图，再用启发式或简化延迟模型选择指令。论文指出了三类不足（第 2.E 节）：

1. 缺少参考 ISA 约束：IR 中的操作可能还要 legalization，且不能直接反映 RISC-V 的立即数、I/O 数量和编码限制。
2. merit 估计不准确：许多方法忽略指令集成到真实处理器后的流水线、寄存器文件访问和关键路径影响。
3. 缺少端到端流程：候选识别、硬件描述、处理器集成、综合和性能/面积评估通常分散在不同工具中。

因此，论文希望把 RISC-V 二进制、热点剖析、候选定制指令和微架构级综合评估连接起来。

## 2. 论文要解决的问题

### 2.1 直接面向 RISC-V ISA 的候选生成

如何从已经编译好的 RISC-V 二进制恢复基本块和数据流图，并在输入/输出、凸性、非法操作和指令编码等约束下枚举可实现的定制指令候选？

### 2.2 考虑微架构影响的候选选择

如何避免只根据“子图包含多少条指令”估计收益，而是把定制功能单元并入处理器模型后，通过综合得到的时钟周期和面积来评估候选？

### 2.3 端到端自动化

如何从 RISC-V 应用二进制和 profiling 数据，自动得到带有 nML（Processor Modeling Language）描述的处理器定制方案，并以较少人工干预完成 RTL/综合级评估？

> 本文主要研究：如何在 RISC-V ASIP 设计中，利用 ISA 感知的候选枚举和微架构感知的综合反馈，自动选择兼顾执行时间与面积的定制指令。

## 3. 核心方法概述

论文提出 CIDRE（Custom Instruction Designer for RISC-V Extensions），一个从 RISC-V 二进制到可综合 ASIP 模型的前后端工具流。它不是语言模型系统，也不是强化学习系统；核心是图枚举、图规范化、贪心/两步前瞻选择，以及 nML/PDG 处理器建模和综合反馈（第 3 节）。

```text
RISC-V 基线二进制 + basic-block profiling + 用户约束
        ↓
自定义反汇编器与控制流分析
        ↓
基本块 DFG 构建
        ↓
受凸性、I/O、立即数和禁用操作约束的穷举子图
        ↓
图 canonical form：合并同构候选
        ↓
生成 nML 模板和 PDG 功能描述
        ↓
集成到 trv64p3 RISC-V 处理器模型
        ↓
Synopsys ASIP Designer / Design Compiler 综合
        ↓
获得时钟周期、面积和估计执行时间
        ↓
选择最优候选，必要时丢弃使总执行时间变差的候选
```

输入是编译到基线处理器的 RISC-V 二进制、每个基本块的执行次数和 I/O/最大指令数约束；输出是定制指令候选、对应 nML 描述以及综合后的处理器评估。模型在系统中不扮演角色，外部工具完成候选生成、验证和评估。

## 4. 实验框架与训练流程

本文不涉及模型训练、SFT、提示词推理、PPO、GRPO 或强化学习。主要采用静态图算法、profiling 和综合反馈。

### 4.1 候选枚举

自定义反汇编器读取 RISC-V 二进制，控制流分析识别基本块，再把基本块转换为 DFG。论文使用 Xiao 和 Casseau 的递归穷举算法，从单节点模式开始，按逆拓扑顺序扩展；凸性和 I/O 约束用于剪枝。允许连通和非连通子图，但排除 load/store 与 jump/branch，以避免昂贵内存访问和控制流改变（第 3 节）。

### 4.2 同构检测与硬件描述

候选通过基于 branch-and-bound 的图 canonicalization 分组。同构候选要求操作类型相同、边的操作数位置相同，交换律操作允许交换相应输入（第 2.C、3 节）。之后根据 I/O 配置选择 nML 指令模板，并自动生成 PDG 中的类 C 功能描述。

### 4.3 微架构反馈与选择

论文使用 Synopsys ASIP Designer 的 `trv64p3` 64 位 RISC-V 处理器模型，包含三阶段流水线并支持 RV64IM。候选会被集成到解码器、寄存器文件、流水线和功能单元中，再生成 RTL 并综合得到时钟周期与面积。

选择算法首先按 merit 选择候选，综合后计算总执行时间；若不优于基线则删除候选。论文另外使用 Bonzini 和 Pozzi 的 two-optimal 一步前瞻策略，缓解单纯贪心可能过早阻塞后续更优候选的问题（Algorithm 1）。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习，因此不存在强化学习奖励函数，也没有训练损失函数。关键目标是候选 merit 与综合后的执行时间。

### 5.1 基础 merit

```text
M(S) = L_SW(S) - L_HW(S)
L_SW(S) = |S|
```

其中 `S` 是一个候选子图；`L_SW` 是子图中软件执行的周期数，论文在基础估计中假设每条操作 CPI=1；`L_HW` 是定制指令硬件延迟，论文的单指令估计也设为 1 周期。

### 5.2 按热点执行次数加权

```text
M(U) = Σ(S∈S_U) (|S| - 1) × f_BB,S
```

`U` 是同构类，`S_U` 是该类中的候选子图，`f_BB,S` 是包含该子图的基本块执行次数。该式让频繁执行的候选获得更高优先级。

### 5.3 微架构感知执行时间

```text
T_execution = f_total × T_clk
T_execution,custom(U) = (f_total - M(U)) × T_clk,custom
```

`f_total` 是应用总指令执行次数，`T_clk` 是基线时钟周期，`T_clk,custom` 是加入候选后经综合得到的时钟周期。若候选使关键路径变长，`T_clk,custom` 可能增大；选择目标是降低总估计执行时间，而不是单独最大化周期节省。

## 6. 实验设置

### 6.1 数据集来源

实验使用 8 个 C 语言嵌入式应用：MiBench 中的 `bitcnts`、`susan`，以及 Embench 中的 `aha-mont64`、`aes`、`crc32`、`md5sum`、`sha256`、`tarfind`。程序使用 RISC-V GCC 工具链、`-O2` 编译；profiling 数据来自作者自研的指令级精确 RISC-V 模拟器。论文说明 Spike 经少量修改也可使用，但实验结果来自自研模拟器（第 4 节）。

论文没有提供训练/验证/测试划分，也没有机器学习数据集；因此不能把这 8 个应用解释为训练集或泛化基准。

### 6.2 模型与工具

* 基线处理器：Synopsys ASIP Designer 的 `trv64p3`，三阶段流水线，RV64IM。
* 处理器建模：nML；指令功能描述：PDG 类 C 语言。
* 综合：Synopsys ASIP Designer 生成 RTL，并使用围绕 Synopsys Design Compiler 的综合框架获得时钟周期。
* 工艺条件：Synopsys 提供的 32/28 nm CMOS 标准单元库，0.85 V，典型工艺角，25 °C。
* 指令/编译工具：RISC-V GCC；profiling：作者自研 instruction-accurate RISC-V simulator。

### 6.3 对比方法

论文的主要对照是同一基线 RISC-V 处理器，而非另一套定制指令生成器。不同 I/O 约束配置之间也进行比较：`(2 inputs, 1 output)`、`(3 inputs, 1 output)` 和 `(3 inputs, 2 outputs)`；每个基准和配置生成 8 条定制指令。

### 6.4 评价指标

| 指标 | 含义 | 趋势 |
|---|---|---|
| `|S|` | 有效候选子图数量 | 用于描述搜索规模 |
| `|U|` | 同构类数量 | 越少表示候选复用/重复越多，但不是性能指标 |
| cycle-based speedup `f_b/f_c` | 只按周期数计算的基线/定制执行比 | 越大越好 |
| `T_clk ↑` | 定制处理器相对基线的时钟周期增幅 | 越小越好 |
| execution-time speedup `T_b/T_c` | 综合后估计执行时间的基线/定制比 | 越大越好 |
| execution-time reduction | 估计执行时间相对基线的下降比例 | 越大越好 |
| area overhead | 定制功能单元导致的处理器面积增幅 | 越小越好 |

## 7. 实验结果与结论

### 7.1 主要结果

表 I 显示，8 条定制指令在不同 I/O 配置下带来不同收益。最佳结果是 `eb-aes`、`(3,2)` 配置：cycle-based speedup 为 2.50，时钟周期增加 1.2%，综合后的 execution-time speedup 为 2.47。所有 benchmark/configuration 的面积增幅低于 24%，平均面积增幅为 11.3%（第 4 节、表 I、图 8/9）。这些是相对于基线处理器的估计/综合结果，不是真实芯片测量。

表 I 的其他代表性结果：`eb-sha256` 在 `(3,1)` 下 execution-time speedup 为 2.29，在 `(3,2)` 下为 2.37，且时钟周期增幅为 0%；`eb-tarfind` 的 `(3,1)` 配置由于时钟周期增幅 4.9%，execution-time speedup 仅为 1.18，低于其 1.24 的 cycle-based speedup。

### 7.2 与传统方法的比较

本文没有报告与其他完整定制指令工具的统一定量对比。论文的核心比较是简化的周期收益估计与 CIDRE 的综合反馈式选择：后者会考虑定制功能单元对关键路径/时钟周期的影响。`mb-susan` 的 `(2,1)` 配置是负面案例：cycle-based speedup 小于 1.01，无法抵消时钟周期增加，因此最终 execution-time speedup 为 0.99，候选被视为不带来实际改进。

### 7.3 与其他 LLM 方法的比较

本文不使用 LLM，也未与 LLM 编译器优化方法比较。

### 7.4 消融实验

论文没有将 CIDRE 模块逐个移除的正式消融实验。不同 I/O 配置和是否考虑时钟周期的结果承担了敏感性分析作用，但不能称为完整 ablation study。

### 7.5 案例分析

图 6 展示 `aha-mont64` 中一个候选：DFG 子图先转为 canonical form，再按“两寄存器输入、一寄存器输出”选择 nML 模板，最后生成 PDG 功能并集成处理器。图 8/表 I 说明，放宽 I/O 约束通常扩大候选空间并提升潜在 speedup，但不同 benchmark 的提升并不单调；图 9 说明面积主要受选中指令复杂度影响，而不直接由操作数数量决定。

## 8. 主要创新点

### 8.1 创新点一：直接从 RISC-V 二进制开始的 ISA 感知流程

已有方法经常以编译器 IR 为入口。CIDRE 直接处理 RISC-V binary，因而把真实 ISA 的立即数、寄存器输入输出和编码限制带入候选生成。这一设计解决的是“候选在 IR 中可行但在目标 ISA 中难以编码/实现”的边界问题。

### 8.2 创新点二：将候选集成到微架构后再估计 merit

CIDRE 不只为候选子图预估原语延迟，而是将候选加入 nML 处理器模型，经过 RTL/综合获取时钟周期和面积，再决定是否保留。论文的实验通过 `mb-susan` 和 `eb-tarfind` 等案例证明，忽略关键路径会高估周期收益。

### 8.3 创新点三：从二进制到处理器评估的端到端自动化

候选枚举、canonicalization、nML/PDG 生成、处理器集成和综合选择被放进一个自动流程。论文报告在预定义约束下，从应用可执行文件到综合处理器无需人工操作；但这依赖特定 ASIP Designer 流程和基线处理器模型。

## 9. 局限性

### 9.1 论文明确承认或展望中的局限

* 当前范围不支持 floating-point、memory access 和 vector instructions；作者把这些列为未来扩展方向（第 5 节）。
* 还没有 compiler support 来自动识别和利用生成的定制指令；作者将其列为未来工作。
* 评估使用预定义 I/O 和最多 8 条指令等设置，不能据此证明对任意 RISC-V 程序都能自动得到最优方案。

### 9.2 阅读后的潜在局限

* 候选枚举是穷举式，且最大候选空间随 DFG 增长；同构类减少重复，但不能消除大规模程序上的搜索压力。
* 指令选择主体是贪心加一步前瞻，不保证全局最优；论文也明确指出单纯贪心可能被早期选择阻塞。
* 执行时间模型假设 CPI=1，且定制指令延迟按一个周期估计，随后用综合得到的时钟周期修正；这仍不是完整的乱序/缓存/内存系统仿真。
* 实验只覆盖 8 个嵌入式 benchmark 和单一 `trv64p3` 基线、单一 32/28 nm 标准单元条件，跨处理器、工艺、编译器和真实硬件的迁移性尚未确认。
* 论文使用有限 benchmark 和模拟/综合反馈，不构成形式化语义等价证明；它验证的是工具流可综合性、性能估计和面积结果。

## 10. 阅读后的研究方向反思

CIDRE 最值得借鉴的是“把硬件约束提前纳入编译/程序优化候选空间”以及“用实际后端综合反馈修正软件层 merit”。对 LLVM/RISC-V 研究而言，这比只替换目标平台更有价值：可以研究 LLVM IR 候选到 RISC-V 实际编码、微架构关键路径和指令选择之间的闭环。

本文不是 LLM 编译器优化论文，因此不能把它的图枚举、综合流程直接包装成 LLM 创新。若将 LLM 加到候选排序或约束生成中，仍必须保留 ISA 合法性检查、硬件综合反馈和面积/时序约束；仅把 Synopsys ASIP Designer 换成 RISC-V 开源工具链也不足以形成新问题。

更合适的定位是：SUPPORTING/B5 硬件 ISA 与编译器背景；它可以作为硬件感知候选选择的 baseline、综合反馈模块设计参考，而不是现成的 LLM 训练框架。

## 11. 可进一步尝试的研究方向

### 11.1 面向 LLVM-RISC-V 后端的综合反馈定制指令选择

#### 研究问题

能否让 LLVM 后端同时表示候选定制指令、寄存器约束、编码约束和综合得到的时钟/面积代价？

#### 与原论文的区别

原论文从已编译二进制开始，尚未自动生成 compiler support；新方向把候选识别、指令选择和代码生成连接起来。

#### 可能的创新点

设计可回写 LLVM 的候选 intrinsic/target pattern，并研究综合反馈如何更新 instruction cost model。

#### 实验框架

```text
LLVM IR → RISC-V 后端候选识别 → 编码/寄存器约束过滤
       → 综合或代理代价模型 → LLVM 指令选择/重编译
       → 仿真与面积/时序评估
```

#### 可行性

需要 LLVM RISC-V 后端、Spike/QEMU 或 RTL 仿真、开源综合工具和可描述定制功能单元的 RTL 模板。

#### 主要风险

编译器 cost model 与真实流水线/存储系统之间可能失配；候选定制指令的 ABI、调度和寄存器分配处理也较复杂。

### 11.2 面向 RVV 的向量定制指令搜索

#### 研究问题

如何将向量长度、掩码、LMUL、访存语义和向量寄存器资源纳入候选枚举与硬件反馈？

#### 与原论文的区别

原论文明确不支持 vector instructions；新方向针对 RVV 的向量资源和可变长度语义，而不是简单换 ISA。

#### 可能的创新点

构造 RVV-aware 子图表示，联合评估向量化收益、寄存器压力、访存行为和功能单元面积。

#### 实验框架

```text
C/LLVM IR → RVV 向量化候选 → RVV 资源/编码过滤
          → RTL/仿真性能反馈 → 帕累托面积-性能选择
```

#### 可行性

需要 RVV 编译器、可运行的 RVV 模拟器或 FPGA/RTL 平台，以及向量功能单元模型。

#### 主要风险

向量内存系统和真实硬件频率会显著影响结果；仅用静态周期模型可能高估收益。

### 11.3 受验证约束的候选定制指令生成

#### 研究问题

如何对候选指令的 RTL、编译器 lowering 和软件参考语义做形式化或等价性检查？

#### 与原论文的区别

CIDRE 重点是性能/面积和综合集成，不提供形式化语义证明；新方向把验证作为一等约束。

#### 可能的创新点

建立从 DFG/LLVM 语义到 PDG/RTL 的可追踪映射，并在候选选择时排除无法证明等价的实现。

#### 实验框架

```text
候选 DFG → 参考软件语义与 RTL 功能生成
         → 等价/属性验证 → 综合获得时序面积
         → 只保留验证通过且有收益的候选
```

#### 可行性

需要 SMT/RTL 等价检查工具、RISC-V ISA 语义模型和可综合的功能单元模板。

#### 主要风险

复杂算子、未定义行为和内存访问会使证明难以扩展；有限测试不能替代形式化验证。

从研究任务位置看，CIDRE 主要属于硬件 ISA/编译器背景与硬件感知指令选择基础设施：它不是 pass/phase 选择器，不是 IR/源码翻译器，也不是 LLM 生成器。它可作为后续研究中“候选定制指令 + 微架构综合反馈”的传统 baseline 或工具模块。

## 13. 一页式总结

| 项目 | 内容 |
|---|---|
| 论文研究任务 | 自动发现并评估 RISC-V ASIP 定制指令 |
| 核心问题 | 让候选生成同时满足真实 ISA 和微架构性能/面积约束 |
| 输入 | RISC-V 二进制、基本块执行次数、I/O/数量约束 |
| 输出 | 定制指令候选、nML/PDG 描述、综合评估后的选择结果 |
| 核心方法 | DFG 穷举、图 canonicalization、贪心/两步前瞻、处理器综合反馈 |
| 使用的模型 | 无机器学习模型；nML 处理器模型 `trv64p3` |
| 使用的编译器工具 | RISC-V GCC、作者自研指令级模拟器；Synopsys ASIP Designer/Design Compiler |
| 是否使用强化学习 | 否 |
| 是否使用形式化验证 | 否；综合与有限工具流检查不等于形式化语义证明 |
| 数据集规模 | 8 个 C 嵌入式应用：2 个 MiBench、6 个 Embench |
| 主要指标 | cycle-based speedup、execution-time speedup、时钟周期增幅、面积开销 |
| 最重要实验结果 | `eb-aes`、`(3,2)` 配置达到 2.47× execution-time speedup；面积增幅全局低于 24%，平均 11.3% |
| 核心创新 | 从 RISC-V binary 到综合处理器的 ISA/微架构感知端到端自动化 |
| 主要局限 | 不支持浮点、访存和向量定制；单一处理器/工艺条件；无 compiler support 和形式化证明 |
| 与 RISC-V 研究的相关性 | 高：论文直接处理 RISC-V ISA、RV64IM 编码和 ASIP 后端，但不是 RVV 或 RISC-V 验证论文 |
| 最适合作为 | 硬件感知定制指令选择 baseline、工具模块和方法参考 |

> 这篇论文最值得学习的是把 ISA 合法性、微架构关键路径、综合时序和面积放进同一个定制指令选择闭环；最主要的局限是候选空间、处理器配置和工艺条件较窄，且没有 compiler support 或形式化证明；如果用于后续研究，最合理的使用方式是作为 RISC-V/LLVM 硬件感知优化的传统 baseline 和综合反馈模块，而不是简单替换平台或直接声称引入了 LLM/验证能力。
