## 1. 研究背景

本文研究面向“极端边缘”（Extreme Edge）的低成本、低功耗、可弯曲电子系统。论文将应用分为短生命周期场景（如智能标签、一次性医疗贴片）和长生命周期场景（如智能纺织、可穿戴医疗、环境监测）。这类系统通常不需要高吞吐处理器，但要求芯片面积、功耗、成本和可制造性很低；柔性集成电路（FlexIC）因此成为目标平台。

传统通用处理器包含目标应用并不使用的指令逻辑，可能浪费面积和功耗。应用专用指令集处理器（ASIP）可以定制指令集，但通常还要为新 ISA 生成编译器、汇编器、链接器和模拟器，并承担定制处理器的验证成本。论文的背景判断是：RISC-V 的开放软件生态可以减少工具链成本，而 RISC-V 的模块化又允许面向应用提取所需指令；但“ISA 模块化”本身并不保证 RTL 实现已经具备指令级模块化。

论文进一步指出，长生命周期应用仍可能需要重新编译软件。若新编译结果包含目标处理器不支持的指令，就需要修改编译器后端或在编译后重定向汇编代码。作者选择后者，并探索以生成式 AI 生成汇编宏，再用功能测试筛选可用宏。

## 2. 论文要解决的问题

### 2.1 如何低成本生成面向应用的 RISC-V 指令子集处理器

目标是从某个应用或应用域实际使用的指令集合出发，自动生成只实现该子集的单周期、32 位 RISC-V 指令子集处理器（RISSP），从而减少面积和功耗。论文同时希望保留既有 RISC-V 软件生态，而不是为每一个定制处理器重新建设完整工具链。

### 2.2 如何降低定制处理器的验证和上市成本

若每次生成定制 RTL 后再进行整体验证，验证会成为重复成本。论文要解决的是如何把验证前置到可复用的“指令硬件块”库：每条指令先独立实现并验证，生成 RISSP 时只组合已有块。

### 2.3 如何处理长生命周期应用的软件更新

长生命周期设备更新软件后，标准 RISC-V 编译器可能生成 RISSP 不支持的指令。论文提出用生成式 AI 把不支持的指令改写成目标指令子集中的汇编序列，并对每个宏进行功能验证。

> 本文主要研究：如何结合预验证的指令级 RTL 库、标准 RISC-V 工具链和受验证约束的生成式 AI 汇编重定向，为极端边缘应用自动生成可部署的 RISC-V 指令子集处理器。

## 3. 核心方法概述

论文的主系统是 RISSP generation methodology。首先将 RISC-V 指令语义实现为独立的 SystemVerilog RTL 指令硬件块，并使用测试、变异覆盖和形式化方法验证，形成预验证的完整 ISA 硬件库。然后将应用编译到 RV32E，提取实际出现的不同指令，抽取相应硬件块，组合成 Modular Execution Unit（ModularEX），再与取指、寄存器文件和存储接口拼接。综合工具负责进一步共享逻辑和删除冗余。

长生命周期更新场景的代码重定向流程如下：

```text
应用源码
  ↓ 使用标准 riscv32-unknown-elf-gcc 编译到完整 RISC-V ISA
目标指令子集 + 初始汇编
  ↓ 识别不受支持的指令
生成式 AI 为不支持指令生成目标子集宏
  ↓ 以原指令语义为目标进行自定义功能测试
验证失败 → 拒绝宏并再次请求候选
验证通过 → 写入 macro.S
  ↓ 带 macro.S 重新编译
仅使用目标指令子集的重定向程序
```

LLM/生成式 AI 在本文中不是完整编译器后端，也不是负责生成整个程序；它只负责将不支持的汇编指令实现为目标指令子集中的宏。硬件处理器的主体仍由 RTL 拼接和综合流程生成。论文实验中使用的是 ChatGPT RISC-V Assembly plugin，正文未说明模型版本、参数规模或训练过程。

## 4. 实验框架与训练流程

本文不涉及模型训练、SFT 或强化学习，主要采用静态硬件生成流程、编译器指令统计、RTL 验证、综合/物理实现和推理阶段的汇编宏生成。

### 4.1 预验证 ISA 硬件库

作者将 RV32I/E 指令语义写成带寄存器文件和内存接口的 SystemVerilog 指令硬件块。每个块先通过 RISC-V Architecture Test SIG 测试、自定义 testbench、自检 testbench，再使用带 SystemVerilog Assertions 的 SymbiYosys 进行形式化验证。还用 Yosys MCY 对 RTL 进行变异，检查测试平台能否发现会改变输出的有效变异。

### 4.2 应用指令子集提取和 RISSP 构造

应用以 RV32E bare-metal 方式编译，不使用 stdlib、libc、libgcc 和 startfiles。作者在 `-O0/-O1/-O2/-O3/-Oz` 下统计静态指令数和不同指令数，选择 `-O2` 作为后续 RISSP 设计基础。目标指令块通过自动化方式组装成 ModularEX，再与固定单元连接。综合工具进行冗余删除和资源共享；该步骤的目标是缩短设计与验证时间，而不是保证全局最小面积或功耗。

### 4.3 集成级验证与物理实现

生成的 RISSP 通过指令/寄存器级检查、RISCOF 架构兼容性测试，并使用 Spike 等 RISC-V 模拟器的签名对照；在处理器级还实现 RVFI 接口，使用 riscv-formal 做有限深度检查。之后进行 FlexIC 工艺综合、频率扫描、面积/功耗评估，以及包含 floorplanning、时钟树插入、布局布线的完整物理实现。

### 4.4 生成式 AI 代码重定向

输入是完整 ISA 编译器生成的汇编、目标指令子集和可选目标（例如允许临时寄存器或尽量缩短代码）。模型针对每条不支持指令生成一个宏。宏若未通过自定义功能测试则被拒绝并重新请求；论文称有效宏通常少于 10 次尝试，但未给出所有指令、所有应用的逐项尝试分布。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习，因此不存在强化学习奖励函数或训练损失函数。

论文中可复述的主要度量定义包括：

```text
EPI = Power(at maximum frequency) / maximum frequency × CPI
```

其中 EPI 是每条指令能耗，功耗取设计在最大频率处的功耗；RISSP 和 RISSP-RV32E 为单周期处理器，CPI 为 1；Serv 为位串行处理器，论文按平均 CPI=32 计算。面积使用正时序裕量范围内的平均 NAND2 等效门数；功耗为静态功耗和动态功耗之和的平均值。上述定义来自第 4.2 节，均是评测指标而非模型训练目标。

代码重定向部分的隐含搜索目标是同时满足功能正确性和用户给出的约束（如允许临时寄存器、缩短 code size），但论文没有给出一个数学形式的奖励函数或损失函数。

## 6. 实验设置

### 6.1 数据集来源

实验包含三类极端边缘应用和 Embench：

| 数据/程序 | 来源与用途 |
| --- | --- |
| `armpit` | 基于柔性传感器的腋下气味分类应用；使用两个决策树的 C 代码作为 benchmark |
| `af_detect` | 柔性 ECG 贴片中的房颤检测 APPT 算法，包含 R 峰检测、RR 间隔计算和 Bloom filter 二分类预测 |
| `xgboost` | 在 Pima Indian Diabetes 数据集上训练/提取决策树后，用 C/C++ 实现作为极端边缘 ML kernel；该数据集有 768 个实例、8 个属性 |
| Embench | 开源嵌入式 benchmark suite，包含 22 个 C 应用；用于提供结构化的嵌入式评测范围 |

代码均编译为 RV32E bare-metal。代码重定向实验使用 `armpit`、`xgboost` 和 `af_detect` 的 `-O2` 初始二进制，并将目标指令子集固定为 `{addi, add, and, xori, sll, sra, jal, jalr, blt, bltu, lw, sw}`。论文没有把所有训练/测试输入、宏候选或完整生成日志作为数据集报告，也未讨论生成式 AI 数据泄漏。

### 6.2 模型与工具

- 编译器：标准 `riscv32-gnu-toolchain` 13.2.0；代码重定向示例使用 `riscv32-unknown-elf-gcc`。
- ISA/IR 层：RISC-V RV32E；硬件实现为 SystemVerilog RTL，不是 LLVM IR 或 MLIR 系统。
- 验证工具：RISC-V Architecture Test SIG、自定义 testbench、Yosys MCY、SymbiYosys、RISCOF、Spike、riscv-formal。
- 硬件工具/平台：Pragmatic 0.6 μm IGZO FlexIC 工艺和商业 EDA 工具；物理实现供电电压为 3 V，统一在 300 kHz 运行。
- 生成式 AI：ChatGPT RISC-V Assembly plugin；正文没有明确说明底层模型、调用次数预算、温度、提示词版本或训练参数。

### 6.3 对比方法

1. `RISSP-RV32E`：使用同一 RISSP 方法生成、但支持完整约 40 条 RV32E 指令的应用无关基线。
2. `Serv`：支持 RV32I 的位串行 32 位 RISC-V 处理器，并配置为 RV32E；其寄存器文件映射到片上存储。
3. 代码重定向部分的“初始二进制”：完整 ISA 编译结果与使用宏重编译后的结果对比。

### 6.4 评价指标

| 指标 | 含义 | 方向 |
| --- | --- | --- |
| 静态指令数/代码大小 | 编译后二进制中静态指令总量或 KB | 越小通常越好 |
| 不同指令数 | 应用实际使用的不同 RV32E 指令数 | 越少可支持更小指令子集 |
| 最大频率 | EDA 约束下仍具有正 slack 的最高频率 | 越高越好，但不是实测应用吞吐 |
| NAND2 等效门数 | 平均面积代理指标 | 越小越好 |
| 平均功耗 | 静态+动态功耗的平均值 | 越小越好 |
| EPI | 按论文定义的每条指令能耗 | 越小越好 |
| 宏重定向代码大小 | 重定向前后程序的字节数 | 越小越好 |
| 功能验证通过 | 生成宏是否与原指令语义相符 | 通过才接受 |

## 7. 实验结果与结论

### 7.1 指令画像和编译优化

Embench 与三个极端边缘应用在不同编译选项下使用 9—32 条不同指令，平均约 19 条；RV32E 约有 40 条指令，因此应用使用完整 ISA 的 24%—86%。三个极端边缘应用的使用比例分别为 `armpit` 42%、`xgboost` 31%、`af_detect` 61%。所有应用的静态指令数平均值在 `-O0/-O1/-O2/-O3/-Oz` 下分别为 2027、1149、1207、1586、1018；对三个极端边缘应用，`-O2` 相比 `-O0` 的静态代码量分别减少 75%、74%、69%。作者因此选择 `-O2`，因为它在代码大小与不同指令数之间取得了合适折中。

### 7.2 综合结果

相对于支持完整 RV32E 的 RISSP-RV32E，面向应用的 RISSP：

- 面积减少 8%—43%，面积以正 slack 频率范围内的平均 NAND2 等效门数计；
- 功耗减少 3%—30%，功耗包含静态和动态部分；
- 最大频率约 1500—1850 kHz；RISSP-RV32E 最高约 1700 kHz，Serv 最高约 2050 kHz；
- EPI 约为 RISSP-RV32E 的同量级优势，并约比 Serv 高效 40 倍；论文还报告 RISSP-RV32E 约比 Serv 高效 35 倍。

这些结果来自综合设计点和论文定义的 CPI/EPI，不应直接解释为真实应用端到端运行时间提升。

### 7.3 物理实现结果

三个极端边缘 RISSP 与两个基线都完成了 FlexIC 物理实现。统一在 300 kHz、3 V、典型/标称 corner 条件下运行。相对于 RISSP-RV32E，`af_detect` 面积减少约 8%，`armpit` 面积约减少 35%，`xgboost` 面积约减少 42%；相对于 Serv，`xgboost` 还减少约 11% 面积。功耗方面，`armpit` 和 `xgboost` 分别比基线约低 8% 和 21%，`af_detect` 与两个基线接近。论文解释 Serv 的触发器占比高，而 FlexIC 工艺中触发器功耗约为 NAND2 门的 10 倍，因此门数更少不必然意味着功耗更低。

### 7.4 生成式 AI 代码重定向

使用 12 条目标指令的最小子集后，重定向二进制的代码大小相对初始完整 ISA 二进制：`armpit` 增加 13%，`xgboost` 增加 5.2%，`af_detect` 增加 36%。`armpit` 和 `xgboost` 的不同指令数变化很小；`af_detect` 的不同指令数从 23 降至 12。作者将其作为可行性展示：宏可以通过功能测试后用于重编译，但代价是代码增大以及潜在运行时变慢。论文没有给出原始运行时间、周期数、每条宏的完整验证结果，也没有证明所有生成宏对任意输入都语义等价。

## 8. 主要创新点

### 8.1 创新点一：预验证的指令级硬件块库

以每条 RISC-V 指令为粒度制作独立 RTL 块，并在加入库前执行架构测试、testbench 自检、MCY 变异覆盖和 SymbiYosys/SVA 形式化验证。该设计把部分验证工作从每个定制处理器的重复成本变成 ISA 库的一次性成本。实验展示了由这些块构造并继续通过集成检查的 RISSP，但没有给出相对于传统 ASIP 的完整验证时间曲线。

### 8.2 创新点二：从应用指令画像自动构造 RISSP

论文将编译器生成的实际指令集合直接作为处理器定制输入，自动抽取对应硬件块并拼接 ModularEX，再交由综合工具进行逻辑共享。价值在于不需要为每个应用重新设计完整微架构和专用软件生态；硬件综合会优化冗余，但论文明确承认该取舍不保证面积/功耗全局最优。

### 8.3 创新点三：带功能拒绝环的生成式 AI 汇编重定向

论文没有让生成式 AI 修改编译器后端，而是保留标准编译流程，在汇编层识别不支持指令，用模型生成宏，并通过测试拒绝不正确候选。该机制把模型输出放在验证门之后，适合处理长生命周期设备的软件更新。创新主要在系统集成和约束闭环，而不是“使用 ChatGPT”本身。

## 9. 局限性

### 9.1 论文明确承认或直接可见的局限

- RISSP 是单周期、标量、按序执行处理器；论文说明方法不适合更复杂的深流水、超标量或乱序处理器。
- 代码重定向实验会增加 code size，作者指出也可能导致运行时变慢；论文没有提供完整的真实性能测量。
- 设计依赖目标应用的静态指令画像。应用、编译选项或输入分布变化后，原 RISSP 的指令子集可能不再覆盖需求。
- RISSP-RV32E 及多数综合比较不包含寄存器文件，论文这样做是为了隔离指令子集影响；因此不能把结果直接当作完整芯片面积/功耗结论。
- 生成式 AI 重定向依赖每条宏的测试验证；正文未给出覆盖全部输入空间的形式化等价证明。

### 9.2 阅读后的潜在局限

- 代码重定向采用汇编宏替换，可能受到调用约定、临时寄存器活跃性、分支范围、异常语义和内存顺序等因素影响；正文只明确讨论了功能测试和 code size，未系统评估这些边界。
- “有效宏通常少于 10 次尝试”是论文给出的概括，不足以判断不同指令、不同模型或不同目标约束下的稳定性。
- 论文的生成式 AI 实验使用 ChatGPT 插件，但没有明确模型版本和完整提示词，因此复现性有限。
- 硬件收益在 0.6 μm IGZO FlexIC 工艺和特定极端边缘应用上测得，不能直接外推到先进硅工艺、RV64、RVV 或复杂 SoC。
- 指令子集不是经过跨输入、跨版本的程序覆盖分析得到的通用安全集合；它更接近给定程序/编译配置的需求集合。

## 10. 阅读后的研究方向反思

值得借鉴的是“模型/工具输出必须经过可执行验证”的系统边界：生成式 AI 只产生候选宏，编译器/测试框架决定是否接受；同时，指令级模块化硬件库为后续针对 RISC-V 扩展的可复用后端组件提供了清晰接口。

不能直接照搬的是把“把完整 ISA 换成某个 RISC-V 子集”当作普适优化。本文目标是低频、低功耗、应用稳定的柔性 MCU；如果只把目标换成 RVV 或另一块 RISC-V 芯片，主要仍是平台迁移。更有研究价值的延伸是把静态指令画像、语义验证和真实性能反馈结合起来，研究“何时删除指令支持、何时保留通用能力”的可拒绝决策。

按 Taxonomy v2，本文最终属于 `GENERATOR / G4_Tool_Test_Fuzz` 更合适：生成式 AI 产生可复用的汇编重定向工具/测试闭环；但硬件 RISSP 部分也有 `SUPPORTING / B5_Hardware_ISA_Compiler_Background` 的背景性质。若按论文中与 AI 编译器最直接的系统输出分类，建议主分类为 `GENERATOR`，二级类为 `G4_Tool_Test_Fuzz`，并以 LLVM/MLIR=否、RISC-V、形式化验证、生成式 AI、编译器代码生成作为标签/证据维度。由于 AI 工具部分实验较小，建议 `Classification_Confidence=MEDIUM`、`Needs_Review=YES`。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RISC-V 的语义等价汇编重定向器

#### 研究问题

如何在不支持的 RISC-V 指令需要被替换时，自动生成短小、寄存器安全且对边界行为等价的指令序列。

#### 与原论文的区别

将论文的测试拒绝环扩展为 LLVM/RISC-V 语义级验证和约束搜索，不能只依赖少量自定义输入测试。

#### 可能的创新点

结合指令语义、寄存器活跃性、代码大小和目标微架构代价，产生带反例的候选排序。

#### 实验框架

```text
LLVM/MIR 或汇编候选 → LLM/搜索生成序列 → Alive2/SMT 或等价检查
        → 反例反馈 → 代码大小与真实硬件周期测量 → 选择候选
```

#### 可行性

需要 LLVM RISC-V 后端、汇编语义模型、等价检查器、QEMU/Spike 及至少一块真实 RISC-V 板卡。

#### 主要风险

特权状态、异常、内存别名和浮点/向量语义可能使局部等价难以定义；形式化检查成本也可能高于编译收益。

### 11.2 硬件响应约束下的指令子集选择

#### 研究问题

如何同时利用指令覆盖、硬件面积/功耗模型和真实运行时反馈，决定应删除哪些指令支持。

#### 与原论文的区别

不把应用的静态 distinct instructions 直接当成唯一决策，而是考虑替换序列的 code size、周期、功耗和更新风险。

#### 可能的创新点

建立“指令子集—可重定向性—硬件代价”的联合 Pareto 选择，并为不确定应用保留安全 fallback 指令。

#### 实验框架

```text
程序画像与候选子集 → RISSP/后端生成 → 语义验证 → 真机/仿真测量
        → 面积功耗与更新成功率反馈 → Pareto 子集选择
```

#### 可行性

可从 RV32E/RV32I 小型程序集开始，再扩展到 RVV 微内核；硬件侧可使用 FPGA/RTL 综合和真实开发板。

#### 主要风险

综合面积和真机性能的相关性可能不稳定；不同工艺和微架构上的结论不能直接共享。

### 11.3 受验证约束的 LLVM/MIR 代码生成代理

#### 研究问题

能否让模型在 LLVM/MIR 或机器指令选择阶段生成候选，而不是在最终汇编文本层做宏替换。

#### 与原论文的区别

候选生成提前到结构化编译器 IR，并让后端负责寄存器、调用约定和调度合法性。

#### 可能的创新点

把结构化动作空间与可验证失败边界结合，形成可审计的代码生成候选库。

#### 实验框架

```text
LLVM IR/MIR → 模型提出结构化改写 → LLVM verifier/后端合法性检查
        → 目标代码与反汇编 → benchmark 真机测量
```

#### 可行性

需要 LLVM pass/MIR 接口、RISC-V 后端、编译器回归测试和可重复硬件测量环境。

#### 主要风险

动作空间、编译时间和训练/推理成本会显著高于单条汇编宏生成；模型改写可能被后续 pass 抵消。

## 12. 与其他已读文献的关系

本 slot 本轮只完成这一篇 MICRO 2025 论文，未在本笔记中虚构与其他同批论文的实验关系。与正式 corpus 中已存在的 RISC-V/MLIR 后端论文相比，本文的重点是“按应用指令集合裁剪处理器 + 预验证硬件块 + 汇编层生成式 AI 重定向”，而不是 MLIR progressive lowering、RVV 向量化或通用代码生成后端。它更适合作为硬件/ISA 协同和验证闭环的工具参考，也可作为研究“生成式 AI 代码候选必须经过语义/功能门控”的 baseline；不宜直接作为 LLVM/MLIR 优化性能的 baseline。

## 13. 一页式总结

| 项目 | 内容 |
| --- | --- |
| 论文研究任务 | 为极端边缘应用自动生成 RISC-V 指令子集处理器，并探索长生命周期软件更新的代码重定向 |
| 核心问题 | 减少定制处理器面积/功耗与验证成本，同时保留 RISC-V 软件生态 |
| 输入 | 应用源码、编译后指令画像、预验证指令 RTL 库、目标指令子集 |
| 输出 | RISSP RTL/物理实现；仅使用目标指令子集的重定向汇编程序 |
| 核心方法 | 预验证指令硬件块 + ModularEX 拼接 + 综合优化 + 生成式 AI 汇编宏与功能拒绝环 |
| 使用的模型 | ChatGPT RISC-V Assembly plugin；具体模型和参数规模未说明 |
| 使用的编译器工具 | riscv32-gnu-toolchain 13.2.0、riscv32-unknown-elf-gcc |
| 是否使用强化学习 | 否 |
| 是否使用形式化验证 | 是；SymbiYosys/SVA、riscv-formal，以及综合等价检查/相关架构验证流程 |
| 数据集规模 | Embench 22 个 C 应用；Pima Indian Diabetes 为 768 实例、8 属性；另有 3 个极端边缘应用 |
| 主要指标 | 静态指令数、不同指令数、频率、NAND2 门数、功耗、EPI、重定向 code size |
| 最重要实验结果 | 面向应用 RISSP 相对完整 RV32E RISSP 减少 8%—43% 面积、3%—30% 功耗；重定向 code size 增加 5.2%—36% |
| 核心创新 | 将预验证指令块作为可复用硬件库，并把生成式 AI 汇编重定向放入功能验证闭环 |
| 主要局限 | 单周期标量处理器；AI 重定向实验小；缺少完整真实性能和跨输入等价证明 |
| 与 RISC-V 研究的相关性 | 高；直接面向 RISC-V ISA 子集、代码生成和处理器/编译器协同，但不等同于 RVV 或 LLVM/MLIR 优化论文 |
| 最适合作为 | 验证闭环、RISC-V 硬件/软件协同和生成式代码重定向的工具参考/对比材料 |

> 这篇论文最值得学习的是把“生成式 AI 产生候选”和“编译器/验证工具决定是否接受”明确分层，并用预验证指令块降低硬件定制的重复验证成本；最主要的局限是实验平台和处理器形态较窄，AI 重定向尚未证明广泛的语义等价与真实性能收益；如果用于后续研究，最合理的使用方式是作为 RISC-V 代码候选验证和硬件/ISA 协同的 baseline，而不是简单把指令子集替换成另一种 ISA 就宣称完成了新优化。
