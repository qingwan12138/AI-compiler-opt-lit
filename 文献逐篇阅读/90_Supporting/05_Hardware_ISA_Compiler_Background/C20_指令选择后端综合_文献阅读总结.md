## 1. 研究背景

主流编译器后端依靠庞大的手写 IR—ISA 匹配规则库；新增 ISA、扩展或自定义配置需要长期专家维护。ARM 与 RISC-V 已公开可执行的形式 ISA 规格，为从语义自动生成“构造即正确”的指令选择规则创造条件，但既有综合方法往往耗时数天，或生成代码明显落后于生产后端（第 1、3 节）。

## 2. 论文要解决的问题

论文要在真实规模 AArch64 与 RISC-V 上，把形式 ISA/IR 语义自动转成可直接纳入 LLVM GlobalISel 的规则库，并同时满足：综合时间可接受、支持多指令序列与立即数约束、规则覆盖真实程序常见模式、生成代码接近手写后端。

> 本文主要研究：如何用规范化索引、样本过滤与 SMT 兜底，把完整指令选择规则综合从“理论可行”推进到生产规模可用。

## 3. 核心方法概述

```text
SAIL ISA 规格 + gMIR 符号规格
→ 符号执行成 SMT-LIB 位向量项
→ 枚举受限 ISA 指令序列并建立规范化项索引
→ 在约 400 个随机输入上缓存项的求值签名
→ 从 CTMark 抽取高频 gMIR 模式（深度≤6）
→ 先查索引寻找结构相似等价项
→ 未命中时按求值签名筛候选，再用 Z3 完备验证
→ 按成本选择有益序列并携带立即数约束
→ 输出 LLVM TableGen 规则，接入 GlobalISel
```

索引无假阳性；随机求值只负责候选过滤，最终 SMT 检查避免假阴性影响完整性。作者将规则库视为对“高频 IR 模式 → 最佳 ISA 序列”的备忘录，而非穷举所有模式（第 4–6 节）。

## 4. 实验框架与训练流程

本文没有学习模型训练。综合阶段先由 SAIL/ISLA 产生 AArch64、RISC-V 指令语义项，再从 CTMark 的真实编译轨迹提取 5000 个高频模式骨架，枚举合法类型后约 7 万模式。规则生成完成后导出 TableGen，与 LLVM 20 的 GlobalISel 集成；SPEC CPU 2017 Integer 用于端到端覆盖率、运行时间和二进制大小评测。

## 5. 奖励函数、损失函数或关键公式

没有 RL 奖励或训练损失。当前序列成本是“序列中所有指令输入操作数总数”，用于在多个等价实现中选择规则，并要求大模式的新序列比各子模式组合更便宜。作者明确承认该模型过于简单，未编码延迟、吞吐、指令数和微架构差异。规范化把交换/结合、常数与位向量等价形态映射到共同项；哈希/Trie 索引将多数等价查询从 SMT 转为结构查找。

## 6. 实验设置

综合机为 32 核 Intel Xeon Gold 6430、256 GB RAM，SMT 求解器为 Z3；最终匹配用 60 线程。AArch64 覆盖核心与 Neon 向量整数指令，RISC-V 使用 `rv64imafd`，但综合本身排除浮点运算；通常 ISA 序列长度≤2，RISC-V 32 位算术允许前置零扩展形成长度 3，IR 模式≤6。真机为 Milk-V SG2042（RV64IMAFD、128 GB）与 Apple M2（16 GiB），LLVM 20，Clang `-O2`，基准为 SPEC CPU 2017 Integer。

## 7. 实验结果与结论

RISC-V 规则库用时 36 分钟、约 8000 条规则；AArch64 不到 2 小时、12448 条规则。65% 模式直接由索引合成；去掉索引总时间约翻倍，去掉随机样本过滤则 5 天仍未结束（第 7.4 节）。

RISC-V 上综合后端几乎没有 GlobalISel fallback，SPEC 运行时间相对手写 GlobalISel 平均慢 2%，二进制平均大 3%。AArch64 平均比 GlobalISel 慢不到 4%、比 SelectionDAG 慢 5%，二进制约大 5%。约 9100 个生成测试（6800 AArch64、2300 RISC-V）中，现有后端近 5000 个需回退到 C++，综合规则可全部声明式处理。结果说明形式规格驱动规则库已能作为新后端的高质量起点，但还不能替代完整后端工程（第 8–10 节）。

## 8. 主要创新点

### 8.1 高频模式备忘录式综合

从 CTMark 真实频率限定 IR 搜索面，并用生产 LLVM 规则统计设定模式/序列上界，避免无用全空间穷举。

### 8.2 规范化项索引 + 求值签名 + SMT 的分层判定

结构相似项走低成本索引，困难等价先用随机求值缩小候选、再以 SMT 保证语义正确，兼顾速度与完备性。

### 8.3 真实 RISC-V/AArch64 GlobalISel 闭环

从官方 SAIL/ASL 规格生成带立即数约束的多指令 TableGen 规则，在真机 SPEC 上量化覆盖率、性能和体积，而非只统计合成规则数。

## 9. 局限性

gMIR 没有正式语义，论文手工定义了大子集，因此“构造即正确”仍依赖这部分规格准确。综合排除浮点、原子等操作，并从 LLVM 手写规则导入缺失模式；陷阱、除法、重定位元数据和部分多输出/跨基本块模式仍需人工或 C++。序列最多通常为 2，至多一个内存操作，未处理复杂别名与内存序。简单操作数成本造成贪心匹配和常量物化次优；完整后端的合法化、寄存器分配、调用约定、寄存器类等仍须手工建设。

## 10. 阅读后的研究方向反思

这篇工作与 RISC-V 的连接不是“换一个目标架构”，而是利用 RISC-V 正式 SAIL 规格降低扩展后端的规则维护成本。最自然的研究缺口是 RVV：向量长度无关语义、掩码/尾部策略、LMUL/SEW 约束和 `vsetvli` 状态使简单位向量项与局部贪心规则不足，需要状态化语义与真实性能成本共同参与综合。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RVV 状态与代价的指令选择规则综合

#### 研究问题

如何从 RVV SAIL/机器语义自动综合包含 `vsetvli`、掩码与尾部策略的多指令 GlobalISel 规则，并在不同 VLEN 实现上保持正确和高收益。

#### 与原论文的区别

原文的 RISC-V 实验集中于标量整数规则，成本只计输入操作数；新方案显式建模向量配置状态、可伸缩长度和微架构测量。

#### 可能的创新点

状态效应规范化、VLEN 参数化 SMT、配置切换感知成本、多规则联合抽取，以及按硬件族校准的鲁棒规则排序。

#### 实验框架

```text
RVV SAIL + gMIR/VP 语义
→ 状态化符号执行 → 高频向量模式
→ 分层索引/SMT 综合 → TableGen 规则
→ LLVM 编译 → QEMU 差分验证
→ 多块 RVV 真机 SPEC/TSVC/内核评测
```

#### 可行性与风险

可先覆盖整数逐元素与归约；风险是 SAIL 符号执行规模、未定义行为、VLEN 量化爆炸和后端合法化与选择阶段边界。

## 12. 与其他已读文献的关系

与 Alive/Alive2、Minotaur、Souper 一样以 SMT 证明位向量等价，但本文输出的是整套目标指令选择规则，不是中端 peephole；与 C12 xDSL→RVV lowering 互补，C12 手写降低链并测真实 RVV GEMM，本文提供从 ISA 规格生成后端规则的方法；与 VecIntrinBench/IntrinTrans 的源级 intrinsic 迁移不同，它工作在 LLVM gMIR—机器指令边界；也可为 C19 STENSO 发现的高层规则提供最终机器后端承接。
