## 1. 研究背景

循环嵌套中的数组表达式经常跨迭代重复计算。传统标量值编号和公共子表达式消除主要处理标量，增强标量替换、特定 stencil 方法或全量搜索又分别受范围、模式和开销限制。论文第 1–3 节强调，数组引用的索引模式和表达式结构需要同时考虑，且冗余可能具有层次性：一个较大的重复表达式中还包含多个可复用的子表达式。

这类优化对科学计算、气候模拟、数值天气和 stencil kernel 有直接价值，但新增辅助数组也会增加内存压力。因此 RACE 同时设计冗余检测、辅助数组生成/压缩和冲突候选选择。

## 2. 论文要解决的问题

### 2.1 识别复杂数组表达式的重复计算

论文要在规则数组引用、嵌套循环和表达式树中识别跨迭代复用，而不是只匹配固定 stencil 模式或简单的同一循环内子表达式。

### 2.2 在冲突候选中选择有收益的冗余

同一 n-ary 表达式可能产生互相冲突的候选子表达式；循环边界往往编译期未知，无法精确计算每个候选的运行时收益。论文将候选选择转成图问题，并提出 inner-dimension-first 启发式降低搜索规模。

### 2.3 控制辅助数组带来的内存代价

辅助数组会保存预计算结果，但如果维度过大，额外访存可能抵消算术减少。因此论文加入 array contraction，并用内存流量和运行时间评估这一权衡。

> 本文主要研究：如何用两级哈希和图选择，在受限嵌套循环中自动检测、消除并压缩数组冗余计算。

## 3. 核心方法概述

RACE 的第一级哈希 reference pattern identifier（rpi）判断数组引用是否具有相同的索引参考模式；第二级哈希 expression redundancy identifier（eri）为表达式编码操作符、操作数和 rpi 等结构信息，从而无需显式两两比较就能发现表达式复用。二叉表达式树上采用线性迭代检测；n-ary 表达式先展平，再用 Pair Graph 表示候选冲突，并通过最大独立集或启发式选择不冲突候选。

```text
带注释的目标循环
        ↓
Flang/Clang AST 解析与表达式树提取
        ↓
rpi：数组引用模式哈希
        ↓
eri：表达式冗余哈希
        ↓
二叉树线性检测 / n-ary 树展平
        ↓
Pair Graph + 最大独立集或 inner-dimension-first
        ↓
辅助数组预计算、表达式重写、数组压缩
        ↓
生成源代码 → LLVM/Clang 编译 → CPU/OpenMP 评测
```

它是 annotation-guided 的源到源优化：开发者在目标循环前后插入指令，RACE 再解析 AST、重写表达式并生成代码。论文不是 LLM、强化学习或形式化验证系统。

## 4. 实验框架与训练流程

本文不涉及模型训练，主要采用静态分析、哈希、图优化和源到源代码生成。

### 4.1 前端与候选提取

实现基于 LLVM 基础设施中的 Flang 和 Clang 前端。工具读取带注释的循环嵌套，提取数组引用和表达式树；当前实现针对完美嵌套循环、无内部控制流、未修改数组和线性索引形式。

### 4.2 二叉树检测与生成

算法按叶节点到根节点计算 rpi/eri，为相同 eri 的表达式建立复用关系。选中的表达式被替换为辅助数组读取，并生成相应预计算循环；随后根据索引范围压缩辅助数组维度。

### 4.3 n-ary 树与启发式选择

结合交换律、结合律和受控分配律展平表达式，处理多个可能互相冲突的二元子表达式。候选选择可形式化为最大独立集；inner-dimension-first（IDF）优先选择内层循环复用和有压缩潜力的候选，以减少 Pair Graph 节点。论文明确指出，IDF 不改变最坏情形指数复杂度，但会显著缩小实际搜索图。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习，因此不存在强化学习奖励函数。关键目标是选择不冲突候选集合 `S`：

```text
maximize |S| - |eri(S)|,    S ∈ independent sets of Pair Graph G
```

其中 `|S|` 近似表示被提取的候选表达式数，`|eri(S)|` 表示为每个不同冗余值付出一次辅助数组预计算的成本。论文进一步通过增加表示每个 eri 的辅助节点，把该目标归约为增强图上的最大独立集问题。该目标是静态近似，不是运行时性能奖励；真实收益还受循环范围、缓存和辅助数组访存影响。

## 6. 实验设置

### 6.1 数据集来源

实验覆盖来自科学计算和 SPEC2000 的循环/内核，包括 POP（Parallel Ocean Program）、WRF、mgrid、derivative、diffusion1、calc_tpoints、j3d27pt、poisson、psinv 等 stencil 或数值计算案例。论文报告了优化前后算术操作、辅助数组数量和运行性能；没有采用机器学习训练集/验证集划分。

### 6.2 模型与工具

工具基于 LLVM 的 Flang/Clang AST 和源到源变换，实验在 Intel 和 AMD CPU 上进行，并测试 OpenMP 多线程扩展。论文提供 Zenodo Docker artifact；当前 PDF 没有在正文中统一给出全部编译器版本和处理器微架构细节。

### 6.3 对比方法

主要对比包括原始 baseline、增强标量替换 ESR+reassociation，以及 RACE 的消融版本：RACE-NR（禁用部分 reassociation）、RACE-NC-NR（同时禁用 array contraction 和 reassociation）。

### 6.4 评价指标

| 指标 | 含义 | 趋势 |
|---|---|---|
| Reduced Ops | 静态分析或运行假设下减少的算术操作比例 | 越大越好 |
| speedup | 相对原始代码的运行加速 | 越大越好 |
| runtime | CPU 执行时间 | 越小越好 |
| memory volume | LLC 与 DRAM 间传输字节量 | 越小越好 |
| OpenMP scalability | 不同线程数的并行加速 | 越大越好 |

## 7. 实验结果与结论

### 7.1 主要结果

在案例分析中，RACE 最多生成 86 个辅助数组并消除 221 次乘法；在 Intel CPU 的 POP `calc_tpoints` 案例中相对原始代码最高达到 3.06× speedup。收益依赖冗余算术强度，`sin/cos` 等计算密集表达式更容易获益。

### 7.2 与传统方法的比较

图 7/8 的总体趋势显示，RACE 通常优于原始代码和 ESR+reassociation；但对 memory-access-intensive 的 `rprj3` 等案例，收益较小，因为额外辅助数组和缓存压力会掩盖算术减少。RACE 的优势来自跨循环数组复用、表达式重关联、IDF 和 array contraction 的组合，而不是单一 hash。

### 7.3 与其他方法的比较

论文讨论了 ESR、ASE、特定 stencil 方法、HSBR、RCE 和 GLORE。RACE 面向更一般的数组表达式和层次冗余；它不是对每个已有方法的统一重新实现，实验主要以原始代码和 ESR+ 为直接 baseline。

### 7.4 消融实验

RACE-NC-NR 的内存流量显著高于 RACE-NR，而 RACE-NR 接近 baseline，说明 array contraction 能缓解辅助数组造成的内存压力。RACE-NR 与完整 RACE 的差异说明 reassociation 和 IDF 还能增加冗余机会。多线程实验中，引入辅助数组没有阻碍 OpenMP 扩展，RACE 在不同线程数下持续优于对比方法。

### 7.5 案例分析

论文以 POP 循环说明四个网格邻域的 `sin/cos` 结果如何跨迭代复用；以 3D stencil 的 mgrid 案例展示更激进的重关联可以暴露新的辅助数组。缩放实验固定 `N × T = 2^31`，改变输入规模和时间步，RACE 在六个代表性 kernel 中除 `diffusion1` 的最大规模点外通常取得最低运行时间。

## 8. 主要创新点

### 8.1 创新点一：数组引用与表达式的两级哈希

rpi 先编码数组索引模式，eri 再编码表达式层次结构，使系统可在线性遍历中识别相同复用模式。与直接比较所有表达式相比，这种分层标识降低了匹配开销，并能处理数组而非仅标量。

### 8.2 创新点二：层次冗余与 n-ary 冲突建模

论文把表达式树展平、候选冲突图和最大独立集联系起来，显式处理多个可复用子表达式互相冲突的问题。该形式化让“选择哪些冗余才值得提取”成为可分析的组合优化问题。

### 8.3 创新点三：内层优先和辅助数组压缩

IDF 以更可能有内层复用、可压缩和缓存收益的候选优先，array contraction 再把辅助数组降到更小维度。实验的内存流量消融证明，这些工程与算法设计对最终性能不可缺少。

## 9. 局限性

### 论文明确承认的局限

- 当前 RACE 重点支持完美嵌套、无内部控制流、数组不被修改和规则线性索引；一般非完美嵌套需要完整合法性分析，留作未来工作。
- RACE 依赖开发者注释指定目标循环，是 aggressive optimization，不是无约束的全程序自动优化。
- Pair Graph 的精确最大独立集仍有指数最坏复杂度；IDF 是缩小实际问题的启发式，不改变理论复杂度。
- 辅助数组可能增大工作集和 cache miss，memory-bound kernel 的收益可能很低。

### 阅读后发现的潜在局限

- 论文主要在 CPU 科学计算和 stencil 场景验证，不能直接推断对 GPU、RVV 或复杂指针别名程序有效。
- 结果依赖 alias/合法性假设、索引形式和实际循环范围；静态 Reduced Ops 不等同于真实硬件 speedup。
- 论文报告源码转换和性能结果，但没有把该方法表述为形式化验证；因此不能把它写成对所有变换都给出机器检查的语义证明。

## 10. 阅读后的研究方向反思

RACE 对研究的启发是把数组索引模式、表达式重关联和内存代价放在同一优化状态中。它与 RISC-V/RVV 的关系是间接的：RVV 后端可以把 RACE 生成的规则循环作为向量化输入，但仅将 CPU 换成 RISC-V 不足以构成新贡献。更有价值的方向是研究辅助数组布局、VL-aware contraction、别名/合法性证据和真实 RVV cache/向量寄存器代价。RACE 适合作为传统编译优化 baseline 或前端变换模块，不是 LLM agent 或强化学习训练框架。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RVV 的冗余消除与数组压缩联合优化

#### 研究问题

如何选择辅助数组维度和布局，使冗余消除同时提高 RVV 向量化覆盖率并降低 cache 流量。

#### 与原论文的区别

加入 RVV 的 VLEN、VL、LMUL、尾部循环和向量寄存器压力，不再只按 CPU 标量/线程结果选择。

#### 可能的创新点

建立 contraction 与向量布局联合代价模型，输出带 RVV 访问模式证据的变换。

#### 实验框架

```text
数组/表达式哈希 → RACE 候选 → RVV 布局候选 → LLVM RVV lowering → 真机/模拟器评测
```

#### 可行性

可基于 LLVM RVV 后端、OpenMP 和 stencil benchmark 实现。

#### 主要风险

不同 VLEN 和 cache 层次可能改变候选排序，模拟器结果不能替代真实硬件测量。

### 11.2 带合法性证明的冗余候选搜索

#### 研究问题

如何为数组别名、边界和循环携带依赖生成可审计的候选合法性证据。

#### 与原论文的区别

从 annotation-guided aggressive optimization 扩展到 translation validation 或局部形式检查。

#### 可能的创新点

把 rpi/eri 候选图与 SMT/符号别名条件结合，拒绝无法证明的候选。

#### 实验框架

```text
候选冗余 → 别名/边界条件 → SMT 或验证器 → 通过候选图选择 → 代码生成
```

#### 可行性

可先从线性数组索引和完美嵌套循环开始，逐步扩展到分支。

#### 主要风险

验证成本可能超过优化收益，且浮点结合律需要单独建模。

## 12. 与其他已读文献的关系

本批次的 Neptune 和 RACE 都处理跨循环计算复用，但对象和证据不同：Neptune 在 GPU tensor compiler 中通过代数修正支持复杂归约融合，RACE 在 CPU 源代码层通过两级哈希和辅助数组消除数组表达式冗余。Neptune 适合作为多硬件张量融合参考，RACE 适合作为数组冗余消除 baseline；二者可以在“高层冗余识别—后端代价选择”方向组合，但不能把一方的实验结果或正确性保证移植给另一方。
