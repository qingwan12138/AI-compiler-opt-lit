## 1. 研究背景

软处理器（soft processor）是用可综合硬件描述和参数配置表达的指令处理器，可部署在 FPGA 上。缓存、分支预测器、除法器、取指宽度等微架构参数可以针对工作负载调节，但参数数量多、参数之间存在非线性关系和依赖约束，人工调优难以覆盖足够大的空间。论文引言指出，FPGA 综合和评估还会显著增加每次试验的成本。

传统黑盒设计空间探索通常使用贝叶斯优化（Bayesian Optimization，BO）：以高斯过程等代理模型估计黑盒目标，再用采集函数在探索与利用之间选择下一个配置。论文指出直接套用标准 BO 有三类问题：类别参数没有自然序关系；设计规范包含不等式、条件和整除约束；每次 FPGA 综合很慢且相近配置会造成重复综合。

## 2. 论文要解决的问题

### 2.1 类别参数

让 BO 能处理分支预测器、乘除法单元等类别变量，识别类别配置的等价结构并减少重复采样。

### 2.2 设计约束

把 FetchWidth ≥ DecodeWidth、条件约束以及 RobEntry/FetchBufferEntry 对 DecodeWidth 的整除关系转为 BO 可用的平滑数值检查函数。

### 2.3 FPGA 评估成本

利用已综合配置的 checkpoint，按配置相似性选择增量综合起点，降低每次候选配置的评估时间。

> 本文主要研究：如何将类别参数、处理器设计约束和增量 FPGA 综合结合到一个面向 RISC-V 软处理器的约束感知贝叶斯优化平台中。

## 3. 核心方法概述

ASPO（Automated Soft Processors Optimization）由参数优化器、约束处理机制和 FPGA 评估框架组成。系统输出软处理器微架构配置，再由仿真、综合和 FPGA 工具评估，而不是生成新的编译器 pass 或源代码。

~~~
处理器参数空间与工作负载
        ↓
类别参数 one-hot 编码 + 自定义协方差核
        ↓
平滑不等式/条件/整除约束检查
        ↓
BO/Expected Improvement 选择候选配置
        ↓
配置匹配器选择相近综合 checkpoint
        ↓
Verilator 仿真 + Vivado FPGA 综合/时序/资源评估
        ↓
反馈执行时间、功耗、资源、时序
        ↓
更新 BO 代理模型和 checkpoint 数据库
~~~

论文支持 RocketChip、BOOM 和 EL2 VeeR，也描述了对设计者自定义处理器的接口。LLM、智能体工具调用和模型训练不是系统组成部分。

## 4. 实验框架与训练流程

本文不涉及模型训练，主要采用贝叶斯优化迭代和硬件评估流程。

### 4.1 配置搜索

表 II 给出的设计空间为：EL2 VeeR 1,920 个配置，RocketChip 31,104 个配置，BOOM 8,398,080 个配置。空间包含类别、整数和布尔参数。

### 4.2 约束处理

候选配置生成时检查线性不等式、条件和整除约束。约束函数以非负值表示满足，负值表示违反。

### 4.3 加速评估

初始配置通过正交数组（Orthogonal Array，OA）覆盖设计空间。每次评估产生的综合 checkpoint 加入数据库；新配置使用加权距离匹配历史 checkpoint。

### 4.4 成本感知搜索

候选到历史配置的最小距离被视为评估成本。带冷却调度的采集函数在早期偏向快速评估区域，后期逐步恢复远距离探索。

## 5. 奖励函数、损失函数或关键公式

本文没有强化学习奖励函数，也没有 SFT、PPO 或 GRPO。

### 5.1 约束函数

不等式约束：

~~~
P_C_inequality(x) = k_a x_a - k_b x_b + t
~~~

负值表示未满足，非负值表示满足。

基本条件约束：

~~~
C_b(x) = min_m c_m(x_m)
c_m(x_m) = -(x_m - a_m)(x_m - b_m)
~~~

析取与合取分别为：

~~~
C_disj = max_i C_i(x)
C_conj = min_i C_i(x)
~~~

整除约束：

~~~
P_C_divisibility(x) = -sin^2(π x_a / x_b)
~~~

当 x_b 可被 x_a 整除时函数为 0，否则为负值。

### 5.2 checkpoint 匹配与采集函数

~~~
MatchConfig(x, w, Q) = argmin_{q∈Q} Σ_i w_i (x_i - q_i)^2
α_cool(x,t) = α(x) / (λ(t) · ĉ(x))
λ(t) = λ_0 · exp(-k t)
~~~

α(x) 是原始采集函数，论文使用 Expected Improvement；ĉ(x) 是到历史配置的最小加权距离。该目标不是奖励模型，而是搜索质量与评估时间的折中。

## 6. 实验设置

### 6.1 数据集来源

论文使用七个 RISC-V 基准：CoreMark、Dhrystone、rsort、qsort、multiply、spmv 和 mm。表 IV 给出的 minstret 为：282,995、186,031、171,154、123,506、42,503、34,466 和 24,744。它们是工作负载和评估任务，不是机器学习训练集。论文没有训练/验证/测试划分，也没有明确进行数据泄漏分析。

### 6.2 模型与工具

| 项目 | 论文明确内容 |
| --- | --- |
| 处理器 | RocketChip、BOOM、EL2 VeeR |
| 仿真 | Verilator |
| 综合/实现 | Vivado，生成资源、功耗、时序报告和 checkpoint |
| FPGA | EL2 VeeR 使用 Zynq UltraScale+ XCZU3CG；BOOM 使用 XCZU6CG |
| 参考频率 | 50 MHz；从 Vivado 报告提取 worst setup/hold slack |
| 初始采样 | 正交数组 |
| 优化器 | ASPO BO 与 VBO、BOOM-Explorer、RCBO 等 |
| LLM/RL | 无 |

EET（Estimated Execution Time）由模拟执行周期除以综合报告最大工作频率得到，是报告驱动的估计指标，不应写成独立的真实板上端到端测量。

### 6.3 对比方法

整体平台比较 Hill Climbing（HC）、Vanilla BO（VBO）、BOOM-Explorer（BE）、Resource-Constraint BO（RCBO）和 ASPO。评估框架比较从头直接综合、固定 checkpoint 和动态 checkpoint 检索。

### 6.4 评价指标

| 指标 | 含义 | 趋势 |
| --- | --- | --- |
| TDT | 总设计时间，单位小时 | 越小越好 |
| IDR | 无效设计比例 | 越小越好 |
| EET | 估计执行时间，单位毫秒 | 越小越好 |
| Evaluation Time | 单配置完整评估时间 | 越小越好 |
| minstret | 退休指令数，用于描述基准复杂度 | 非优化目标 |

## 7. 实验结果与结论

### 7.1 评估框架加速

表 V 中，EL2 VeeR 的平均评估时间由直接评估的 11.4 分钟降为固定 checkpoint 的 10.4 分钟和 ASPO 动态检索的 9.1 分钟；RocketChip 为 45.4、37.7、33.1 分钟；BOOM 为 81.2、65.2、54.1 分钟。动态匹配比固定 checkpoint 更快，但这是综合评估流程加速，不是模型推理速度结果。

### 7.2 设计生产率

表 VI 的实验覆盖三个处理器和七个工作负载。ASPO 在多数任务上取得较小 TDT 和较低 IDR。BOOM 的 spmv 中，ASPO TDT 为 9.12 小时，RCBO 为 27.96 小时，BE 为 35.00 小时，VBO 为 28.15 小时；论文报告相对 RCBO、BE、VBO 分别节省 67.4%、74% 和 67.6%。

ASPO 的 IDR 并非所有任务都为零；例如 BOOM 的 spmv IDR 为 36%，因此不能概括为完全避免无效设计。

### 7.3 设计质量

表 VII 显示 ASPO 在 21 个处理器-任务组合中的 17 个取得最佳 EET，其余与其他方法相近。BOOM 的 multiply 中，ASPO 为 0.70 ms，默认配置为 1.07 ms，论文据此报告约 34.6% 降低。该结果是由模拟周期和综合报告最大工作频率计算的 EET。

### 7.4 组件证据与边界

论文没有提供每个组件单独移除后的完整消融表；但对直接综合、固定 checkpoint 和动态 checkpoint 的对照支持 checkpoint 复用和动态选择的作用。论文未来工作提出扩展到 SoC、自定义指令处理器和应用专用多核，这些扩展尚未实现。

## 8. 主要创新点

### 8.1 面向类别参数的自定义 BO 核

ASPO 在核函数计算前恢复 one-hot 的离散结构，使相同类别配置共享核函数处理，减少重复评估。实验支持其整体系统价值，但没有独立量化该核的贡献。

### 8.2 将设计规范转为平滑约束

用 min/max 处理合取/析取，用连续函数处理不等式和整除关系，让 BO 区分接近可行与明显不可行的候选，减少综合阶段才发现非法配置的浪费。

### 8.3 动态 checkpoint 检索与成本感知采集

由匹配器自动选择历史 checkpoint，并在采集函数中加入评估距离和冷却调度。表 V 支持该机制降低单配置评估时间。

### 8.4 统一 RISC-V 软处理器平台

平台接入 RocketChip、BOOM、EL2 VeeR，并公开复现实验脚本。工程化和可扩展接口有价值，但“使用 RISC-V”本身不是单独的算法创新。

## 9. 局限性

### 9.1 论文明确或直接可见的局限

- 评测只覆盖三个软处理器、七个基准和两类 Zynq UltraScale+ FPGA，跨厂商、跨 ISA 和更多处理器的迁移性没有证明。
- 论文使用定义的参数子集；SoC、自定义指令和多核扩展属于未来工作。
- 依赖 Vivado、Verilator 和 checkpoint 生态，复现环境可能受工具版本限制。
- λ_0 和 k 经验设定，正文没有系统敏感性分析。
- 类别核、约束函数、checkpoint 检索和成本采集缺少完整的逐项独立消融。

### 9.2 阅读后发现的潜在局限

- EET 是由模拟周期和综合报告频率计算的估计值，不等于每个任务的真实板上端到端测量。
- 带权欧氏距离未必能准确反映小参数改变引起的大范围重综合。
- 平滑约束代理不保证覆盖所有工具生成器、资源限制或综合失败模式。
- 论文只在给定预算内比较方法，不能证明找到了全局最优配置。
- 系统输出处理器配置，不是 LLVM IR、源码、汇编或可复用编译器 pass，因此与 LLM 直接生成编译变换的工作不同。

## 10. 阅读后的研究方向反思

值得借鉴的是把合法性、硬件评估成本和性能反馈共同纳入搜索闭环；把综合失败、资源超限和评估时间作为一等信息，比只用运行时间更接近真实硬件设计。

不能直接照搬的是 ASPO 的 BO 数学形式、Vivado checkpoint 接口和 Zynq 资源模型。若只把目标处理器换成另一种 RISC-V 实现，创新性有限。ASPO 更适合作为硬件后端评估器、约束感知搜索 baseline 或 RISC-V/FPGA 反馈模块，而不是 LLM 训练方法。

## 11. 可进一步尝试的研究方向

### 11.1 RISC-V HLS/编译变换联合搜索

**研究问题：** 联合搜索 C/C++/HLS 变换、pragma 和 RISC-V 软处理器参数。

**与原论文区别：** 原论文主要搜索处理器参数，新方向还要保证程序语义、HLS 可综合性和变换收益。

**实验框架：**

~~~
源程序/HLS kernel → 合法变换候选 → RISC-V/FPGA 参数
→ 约束检查 + HLS/编译 → 仿真/综合/板级评估 → 反馈搜索
~~~

**可行性与风险：** 可复用 ASPO 的硬件反馈；但联合空间更大，语义验证和综合失败会成为瓶颈。

### 11.2 学习综合成本

**研究问题：** 从综合日志、组件变化和 checkpoint 命中结果学习更准确的增量综合成本模型。

**与原论文区别：** ASPO 使用带权欧氏距离，新方向直接学习参数变化到综合时间/资源变化的关系。

**实验框架：**

~~~
历史配置与日志 → 组件/时间特征 → 成本预测模型
→ BO 选择质量/代价折中的配置 → 新日志反哺
~~~

**风险：** 工具版本、并行资源和缓存状态可能使模型学到环境噪声。

### 11.3 多 FPGA/多 ISA 可迁移约束表示

**研究问题：** 将处理器规范、资源限制和性能目标表示为可迁移的约束层。

**与原论文区别：** 原论文主要面向三个处理器和实验 FPGA，新方向强调跨工具链和跨器件迁移。

**实验框架：**

~~~
处理器/FPGA 规范 → 统一约束 schema → 后端适配器
→ 各平台综合/仿真 → 跨平台质量与迁移成本比较
~~~

**风险：** 不同综合器的时序、资源和增量综合语义不一致，统一 schema 可能只能覆盖公共子集。

## 12. 与其他已读文献的关系
