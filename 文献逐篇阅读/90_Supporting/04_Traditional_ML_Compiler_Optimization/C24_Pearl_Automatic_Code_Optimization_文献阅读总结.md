## 1. 研究背景

计算密集型程序的大量运行时间通常集中在循环中，但循环变换的组合空间非常大。Tiramisu、Halide、TVM 和 Pluto 等编译器可以执行循环优化，但穷举搜索不可行；Tiramisu 自动调度器的搜索空间被论文估计为约 10^170 个候选。已有强化学习方法往往只处理特定程序、特定领域或 pass 顺序，不能同时支持一般循环嵌套、多面体变换和训练外程序泛化。

论文因此研究一种能够从随机程序中学习优化策略、再直接应用到未见程序的自动调度器，以降低搜索开销并扩大可优化程序范围。

## 2. 论文要解决的问题

### 2.1 一般循环嵌套的优化选择

给定由循环嵌套和张量计算组成的 Tiramisu 程序，系统需要决定应用哪些变换、变换顺序、变换参数以及变换作用于哪个循环分支。

### 2.2 训练外程序的泛化

已有 RL 优化器可能在训练时记住目标程序，部署时仍只能优化训练过的程序。Pearl 试图训练随机程序后优化完全不同的 benchmark。

### 2.3 RL 训练成本

每次动作都可能需要合法性检查、编译和目标硬件执行；论文称一次训练可能持续数周。因此需要复用已计算的合法性和执行时间，并改善 actor-critic 的初始化。

> 本文主要研究：如何用深度强化学习在 Tiramisu 中自动选择面向一般循环嵌套的多面体变换，并泛化到训练中未出现的程序。

## 3. 核心方法概述

Pearl 将 Tiramisu 循环嵌套表示为抽象语法树（AST），利用节点特征、读写访问矩阵和当前遍历分支构成状态；GATv2 图神经网络提取图级表示，actor-critic 网络使用 PPO 预测动作。动作包含循环并行化、展开、分块、倾斜、交换、反转及参数。

```text
Tiramisu 程序
    ↓
循环嵌套 AST、节点特征、读写访问矩阵
    ↓
GATv2 消息传递与池化
    ↓
PPO actor-critic 选择当前 AST 分支的变换动作
    ↓
Tiramisu 合法性检查、编译、目标硬件执行
    ↓
由 speedup 得到对数奖励
    ↓
继续遍历下一分支或结束 schedule
```

系统不使用 LLM。正确性依赖 Tiramisu 的多面体依赖分析和变换合法性检查，而不是形式化等价证明。

## 4. 实验框架与训练流程

### 4.1 状态和动作建模

论文把 AST 中的 iterator 和 computation 编码为固定长度节点向量。iterator 特征包括上下界、并行化/反转标签、展开因子、分块大小、倾斜因子和 focus tag；computation 特征包括数据类型、绝对顺序以及读写访问信息。GATv2 使用 2 层消息传递、4 个 attention head 和隐藏维度 128，再接 MLP、策略头和值函数头。

### 4.2 PPO 训练

代理逐个 AST 分支处理循环。动作由 `(T, I, C, F)` 表示，`T` 是变换类型或 `Next`，`I/C` 指定受影响的迭代器和计算，`F` 是变换参数。论文实现的动作空间共 56 个动作；选择 `Next` 后转向从左到右的下一分支。

### 4.3 训练加速

训练数据包括 2500 个随机生成的 Tiramisu 程序，代理探索到的独特 schedule 约 45,000 个。合法性检查和执行时间缓存后，后续训练可复用已有 `(program, schedule)` 结果。另以 26,000 个程序图—未优化执行时间样本，用 MSE 预训练 GNN、前馈层和值网络，再把权重用于 PPO 初始化。论文没有采用 SFT 或 LLM 训练。

## 5. 奖励函数、损失函数或关键公式

论文定义最终 speedup 为各步中间 speedup 的乘积，并用对数把乘积转为可累加奖励：

```text
τ_f = ∏ τ_i
r_t = log(τ_t)
```

其中 `τ` 是原始执行时间除以变换后执行时间；大于 1 表示变换后更快。论文在训练中使用以 4 为底的对数来缩放奖励。非法动作被赋予 speedup 1，不应用于原程序，由代理学习哪些动作有价值。actor-critic 预训练使用均方误差预测未优化程序执行时间。

## 6. 实验设置

### 6.1 数据集来源

训练集是 2500 个随机生成的 Tiramisu 程序，生成方法沿用 Tiramisu 自动调度工作。预训练使用 26,000 个程序图和未优化执行时间数据。评测 benchmark 包含 blur、cvtcolor、doitgen、heat2d、heat3d、jacobi2d、mvt 和 seidel2d，覆盖图像处理、深度学习/张量、线性代数和科学计算类型。论文未报告训练/验证/测试的传统数据集划分。

### 6.2 模型与工具

使用 Tiramisu 编译器、GATv2、PPO 和 actor-critic 网络。训练环境为 4 个节点，每个节点是 28 核 Intel Xeon E5-2680 v4、CentOS 8；论文用目标硬件执行程序获得时间。具体 Tiramisu 版本未明确说明。

### 6.3 对比方法

对比 Tiramisu 自动调度器、使用 ILP 的 Pluto，以及 RL 编译器 HalideRL。HalideRL 对每个 benchmark 单独训练；PolyGym 未作为性能 baseline，因为论文认为它提供环境而没有深度 RL agent。

### 6.4 评价指标

主要指标是相对未优化程序的 execution-time speedup，评测时每个 benchmark 的 schedule 执行 30 次并取最小值以降低噪声。训练成本用收敛时间比较，动作策略预测时间也单独报告。

## 7. 实验结果与结论

### 7.1 主要结果

Pearl 相对未优化代码的几何平均 speedup 为 3.16×；相对 Tiramisu 自动调度器的几何平均 speedup 为 2.02×，相对 Pluto 为 3.36×。表 3 中 Pearl 的八个 benchmark speedup 均不低于 1。

### 7.2 与传统方法比较

Tiramisu 自动调度器、Pluto 和 Pearl 的几何平均 speedup 分别为 1.56、0.94 和 3.16；这些数值都以相应 benchmark 的未优化执行时间为基线。cvtcolor 中 Tiramisu 更好，论文解释为它先交换循环再并行化，避免并行化仅有三个迭代的外层循环带来的开销。

### 7.3 与 RL 方法比较

HalideRL 在 blur、doitgen 和 jacobi2d 三个 benchmark 上崩溃，因此论文未报告这三项结果；其余项目中 Pearl 的总体几何平均更高。

### 7.4 消融实验

GAT 略优于 GCN 和 GraphSAGE；最佳网络为 2 层 GAT、3 层 MLP、隐藏维度 128。合法性/执行时间缓存使代理在 45 小时达到最佳平均奖励。actor-critic 预训练版本几何平均 speedup 为 3.16，未预训练版本为 2.15；未预训练版本在 heat2d 上未找到有效优化，在 seidel2d 上得到 0.65 speedup。

### 7.5 搜索开销

在报告的 benchmark 上，Pearl 平均用 33.36 ms 预测优化序列，论文称比 Tiramisu 调度器快 563.67×。该指标是策略识别/搜索时间比较，不等同于包含编译和真实执行的端到端总时间。

## 8. 主要创新点

### 8.1 面向 AST 分支的动作表示

Pearl 不把每个“变换—分支—迭代器”直接展开为巨大动作集合，而是按 AST 分支渐进遍历，并用 `Next` 切换分支。价值在于保留了对不同循环位置和参数的选择能力，同时把动作空间固定为 56 个动作。

### 8.2 支持一般循环嵌套的 PPO 自动调度器

论文把多面体变换纳入统一 RL agent，并声称可从随机程序学习后泛化到未见 benchmark；这比只做 pass 排序或只面向单一深度学习图的 RL 系统更宽。

### 8.3 面向 RL 研发的缓存与预训练

缓存合法性和执行时间减少重复编译/执行；用程序执行时间预测任务初始化 actor-critic。消融结果表明二者都对训练或最终 speedup 有帮助，但预训练目标不是直接预测最优 schedule。

## 9. 局限性

### 9.1 论文明确承认的局限

当前只支持六类循环变换，作者计划扩展更多循环和数据布局变换，并探索直接使用原始文本状态。论文的程序抽象要求代码能表示为循环嵌套序列并操作张量。

### 9.2 阅读后发现的潜在局限

评测规模为 8 个 benchmark，且论文没有给出传统训练/验证/测试划分；“泛化”主要由随机程序训练到固定 benchmark 的设置支持。方法依赖 Tiramisu、多面体合法性分析和目标硬件执行，不能直接推出对 LLVM、RISC-V 或含复杂控制流程序同样有效。33.36 ms 只描述策略预测，不能替代端到端编译时间。

## 10. 阅读后的研究方向反思

值得借鉴的是将代码结构、访问关系和当前变换状态共同编码，并把合法性检查放入 RL 环境。核心贡献在于 Tiramisu 多面体场景下的动作表示和训练机制，不能仅把 Tiramisu 替换为 RISC-V 后端就宣称同等创新。对 LLVM/RISC-V 研究而言，Pearl 更适合作为“结构化状态+反馈调优”的方法参考；需要重新定义 LLVM IR 状态、RVV 合法性、真实硬件代价和跨微架构迁移证据。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RVV 后端的结构化动作调优

#### 研究问题

如何用 LLVM IR、循环依赖和 RVV 向量长度信息选择向量化、展开、尾部处理与 lowering 组合。

#### 与原论文的区别

目标从 Tiramisu 多面体变换转为 LLVM/RVV 后端，并要求真实 RISC-V 硬件或可信模拟器证据。

#### 可能的创新点

将 VLEN、LMUL、访存模式和寄存器压力作为动态状态，并加入代码正确性与真实周期的双重约束。

#### 实验框架

```text
LLVM IR/循环分析 → RVV 动作候选 → 合法性与 lowering → 真机性能反馈 → PPO 更新
```

#### 可行性

需要 LLVM RISC-V 后端、RVV 工具链、基准套件和具备 V 扩展的硬件。

#### 主要风险

真实硬件噪声、编译时间和向量化合法性会使奖励稀疏；仅依赖 QEMU 不能替代真实周期。

### 11.2 跨硬件的 schedule 迁移

研究不同 CPU/RVV 参数下缓存的 schedule 是否可迁移，并用少量目标平台反馈校正策略；区别在于新增硬件条件建模，而不是简单复现 Pearl。

## 12. 与其他已读文献的关系

本批次 C25 DeCOS 同样用 RL 选择编译优化序列，但 DeCOS 面向 LLVM IR、硬件性能计数器和通用 C/C++ 热函数，Pearl 面向 Tiramisu 的循环嵌套与多面体变换。Pearl 可作为结构化循环动作和 PPO 环境的 baseline，DeCOS 可作为 LLVM pass 选择、动态反馈和跨硬件迁移的对照；二者可以组合为“结构化中间表示动作+硬件反馈”，但不能把两种实验结果直接横向比较。

## 13. 一页式总结

| 项目 | 内容 |
|---|---|
| 论文研究任务 | 自动优化一般循环嵌套 |
| 核心问题 | 多面体变换空间过大且既有 RL 难泛化 |
| 输入 | Tiramisu 程序的循环 AST、访问矩阵和节点状态 |
| 输出 | 优化变换序列及参数 |
| 核心方法 | GATv2 表示 + PPO actor-critic + 分支渐进动作 |
| 使用的模型 | GATv2、MLP、PPO；无 LLM |
| 使用的编译器工具 | Tiramisu、合法性/依赖分析、目标硬件执行 |
| 是否使用强化学习 | 是，PPO |
| 是否使用形式化验证 | 否；使用多面体合法性检查 |
| 数据集规模 | 2500 个随机程序；约 45,000 个独特 schedule；26,000 个预训练点 |
| 主要指标 | execution-time speedup、训练/预测时间 |
| 最重要实验结果 | 几何平均 3.16× 相对未优化，2.02× 相对 Tiramisu 调度器 |
| 核心创新 | AST 分支动作表示、未见程序泛化、缓存和 actor-critic 预训练 |
| 主要局限 | 依赖 Tiramisu 和循环/张量抽象，评测规模有限 |
| 与 RISC-V 研究的相关性 | 中：可借鉴结构化反馈调优，但论文未评测 RISC-V |
| 最适合作为 | RL 调优方法参考和结构化动作 baseline |

这篇论文最值得学习的是把循环位置和变换参数纳入可扩展动作表示；最主要的局限是其结论依赖 Tiramisu 多面体场景。如果用于后续研究，合理方式是迁移状态/动作设计并补充 LLVM/RVV 与真实硬件证据，而不是只替换目标架构。
