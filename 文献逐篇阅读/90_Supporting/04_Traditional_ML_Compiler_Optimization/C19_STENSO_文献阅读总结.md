论文题目：**Tensor Program Superoptimization through Cost-Guided Symbolic Program Synthesis**

作者：Alexander Brauckmann、Aarsh Chaube、José W. de Souza Magalhães、Elizabeth Polgreen、Michael F. P. O’Boyle

发表时间：2026

发表平台：CGO 2026，DOI: 10.1109/CGO68049.2026.11395198
代码/数据/工件：作者工件：[STENSO Zenodo artifact](https://zenodo.org/records/17638077)
元数据核验来源：[CGO 2026 官方议程及预印本](https://2026.cgo.org/details/cgo-2026-papers/45/Tensor-Program-Superoptimization-through-Cost-Guided-Symbolic-Program-Synthesis)；[DOI](https://doi.org/10.1109/CGO68049.2026.11395198)

关键词：张量程序、超级优化、符号执行、程序合成、代价模型、分支定界

> 本文档基于 13 页作者公开 PDF 全文整理。

## 1. 研究背景

NumPy、JAX/XLA 与 PyTorch-Inductor 依赖固定的规则和启发式，难以覆盖同一张量语义的全部高层表达。传统调度搜索仍受预定义变换空间约束；无约束超级优化虽能追求全局最优，却遭遇组合爆炸。论文因此在张量 DSL 层寻找编译器漏掉、但数学上等价且更快的程序（第 1–2 节）。

## 2. 论文要解决的问题

核心问题是：如何不预先枚举重写规则，系统搜索符号等价的张量程序；又如何使搜索在可接受时间内结束，并让候选的优化目标贴近目标硬件真实性能，而不只依赖 FLOP 数。

> 本文主要研究：用符号草图合成与测量驱动的分支定界，在给定 DSL 语法内找到成本最低的等价张量程序。

## 3. 核心方法概述

```text
输入 NumPy 程序
→ MLIR-HLO/标量 MLIR 表示
→ 对代表性符号输入执行，得到目标符号表达式
→ 深度为 2 的自底向上枚举生成带洞草图
→ 自顶向下递归填洞；SymPy 求解符号参数
→ “目标表达式被简化”约束保证搜索推进
→ 预剖析草图代价求部分程序下界
→ 分支定界剪去不可能优于当前最优解的分支
→ 输出等价且估计成本最低的 DSL 程序
```

搜索不是在既有 rewrite 列表上排列组合，而是从 DSL 语法生成草图并解洞；因此可反向归纳出编译器尚未拥有的规则（第 3–5 节）。

## 4. 实验框架与训练流程

本文没有机器学习训练。离线阶段对草图库逐项在目标硬件上测量并形成查表代价；针对每个输入程序执行完整合成搜索。合成出的内核可缓存复用，发现的模式还可人工提炼为 JAX/PyTorch 等编译器的重写规则。工件提供 Docker 化构建、合成、基准和绘图流程。

## 5. 奖励函数、损失函数或关键公式

没有 RL 奖励或神经网络损失。搜索目标是最小化部分程序各草图预测量成本之和 `cost_total`。当当前部分候选的成本下界不小于已知最佳完整程序 `cost_min` 时，整条分支被剪枝。另一硬约束要求每次草图应用都简化剩余符号规格；论文也讨论 FLOP 代价，但最终实验采用测量代价，以区分 FLOP 相同而运行成本不同的运算。

## 6. 实验设置

基准共 33 个：21 个来自公开 GitHub 的实际数值程序、12 个合成表达式，最长含 6 个操作。后端比较 NumPy 2.2.6、JAX 0.7.1 和 PyTorch 2.8/Inductor。合成机为 AMD Ryzen 9 7950X、64 GB；性能另在 Intel i7-8700K（32 GB）和 Apple M3 Pro（18 GB）复测。消融比较仅简化目标、加入分支定界，以及类似 TASO 的自底向上枚举基线；超时阈值 10 分钟。

## 7. 实验结果与结论

三平台均有稳定收益。在 AMD 上，几何平均加速为 NumPy 3.8×、JAX 1.6×、PyTorch 1.6×；Intel 上分别 3.7×、1.5×、1.5×；Apple 上分别 3.7×、1.9×、1.2×（图 4）。只用简化目标时约四分之一基准超时；加入分支定界后全部合成成功，绝大多数低于 200 秒，只有 `diag_dot` 和 `vec_lerp` 略超 200 秒，且所得解与未剪枝配置一致（第 7.2 节）。

作者将结果归为代数化简、恒等替换、冗余消除、强度削弱和向量化五类。AMD 上向量化类几何平均为 NumPy 10.7×、PyTorch 4.4×、JAX 2.9×；`vec_lerp` 的 NumPy 单例达到 16.4×，`log_exp` 达 23.6×（第 7.3 节）。结论是高层符号合成能发现固定规则编译器漏掉的全局改写，但可扩展性仍由语法和草图深度决定。

## 8. 主要创新点

### 8.1 从符号规格到张量 DSL 草图的超级优化

把具体输入符号执行为数学规格，再用带洞草图与代数求解构造实现，不依赖预置 rewrite 集。

### 8.2 简化约束与测量代价的双重引导

前者保证递归进展，后者以硬件剖析结果形成分支下界，在保持最优性的同时显著缩短搜索。

### 8.3 把一次合成结果沉淀为缺失规则

生成程序被归纳为五类可复用变换，可反哺常规编译器或 e-graph 规则库；论文同时公开 33 个基准和复现实验工件。

## 9. 局限性

正确性是相对于有限 DSL 语义和符号代数的“构造即正确”，论文未给出独立 SMT/翻译验证器，也未深入处理浮点重关联、NaN、溢出或近似语义。程序最多 6 个操作，草图深度固定为 2；扩大语法会指数增长。每个较大基准约需 200 秒，仍不适合在线通用编译。实验只在 CPU 上完成，GPU/TPU 的“硬件无关”是基于重新剖析的推断，尚无实测；代价可加但真实算子融合、缓存和并行交互未必可加。

## 10. 阅读后的研究方向反思

STENSO 最有价值的不是另一个 NumPy 优化器，而是“从高层合成候选规则，再交给低层编译器验证和部署”的桥梁。对 RISC-V/RVV，直接把 CPU 换成 RISC-V 贡献有限；更关键的是把可伸缩向量长度、LMUL、掩码/尾部策略、后端可合法化性和真机 PMU 纳入代价与正确性边界。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RVV 的验证引导张量重写发现

#### 研究问题

如何从张量 DSL 自动合成在多种 VLEN/LMUL 下都合法，并能被 LLVM RVV 后端稳定降低的高层重写。

#### 与原论文的区别

原文只用符号等价与 CPU 草图剖析；新方案增加浮点/整数语义验证、后端 lowering 成功率和跨 VLEN 真机反馈。

#### 可能的创新点

分层代价下界、合法化失败剪枝、跨 VLEN 鲁棒目标，以及由 Alive2/差分测试提供的反例约束。

#### 实验框架

```text
张量程序 → STENSO 式草图合成
→ 精确/浮点语义验证
→ MLIR/LLVM/RVV lowering
→ QEMU + 多块 RISC-V 真机测量
→ 跨 VLEN 鲁棒排序 → 生成候选重写规则
```

#### 可行性与风险

可先限制为逐元素整数、归约和矩阵向量小核；风险是浮点等价、真实性能噪声、LLVM 合法化阶段改变代价排序。

## 12. 与其他已读文献的关系

与 Minotaur/Souper 同属超级优化，但 STENSO 在高层张量 DSL 上用草图与符号代数构造程序，而非 LLVM 位向量/SMT peephole；与 Mirage 的多层张量超优化相比，STENSO 聚焦高层缺失改写和可解释规则；与 C16 Foresight、C17 EggMind 的 EqSat 路线互补：STENSO 可发现新规则，EqSat 系统负责高效组合已有规则；与 LPO 相似地服务“发现编译器漏掉的优化”，但不依赖 LLM，且通过受限语法构造等价候选。

## 13. 一页式总结

| 项目 | 内容 |
|---|---|
| 论文研究任务 | 张量 DSL 程序超级优化与缺失规则发现 |
| 输入/输出 | NumPy 程序 / 符号等价、成本更低的 NumPy 程序 |
| 核心方法 | 符号执行、草图合成、代数求解、测量代价分支定界 |
| 使用的模型 | 无神经模型 |
| 是否使用强化学习 | 否 |
| 是否使用形式化验证 | 符号构造保证受限 DSL 等价；无独立通用验证器 |
| 数据集规模 | 21 个真实 + 12 个合成基准 |
| 主要指标 | 运行时加速、合成时间、超时率 |
| 最重要结果 | AMD：NumPy 3.8×，JAX/PyTorch 各 1.6×；分支定界使全部基准完成 |
| 核心创新 | 不依赖预置规则的张量草图超级优化 + 硬件测量下界 |
| 主要局限 | 小表达式、搜索指数增长、CPU-only、浮点语义边界不充分 |
| 与 RISC-V 相关性 | 中高；代价模型可重剖析，但 RVV 合法性和真机评估尚未完成 |
| 最适合作为 | 张量 rewrite 发现与超级优化基线 |

> 最值得复用的是“符号规格 + 受限草图 + 可证明安全的代价剪枝”；最需要补强的是独立语义验证和跨硬件、跨向量长度的真实性能闭环。
