## 1. 研究背景

传统 SSA/CFG 编译器在原图上破坏式执行优化，先前程序状态随 pass 被丢弃，因此不同 pass 顺序可能得到不同结果。EqSat 用共享结构保留多个等价表达式，但现有 e-graph 更自然地处理表达式树/DAG；任意控制流通常要先规范化成结构化区域或 RVSDG（第 1 节）。

## 2. 论文要解决的问题

论文探索能否不把 CFG 先转成树或区域 IR，直接以控制流内的指令序列为等价单位，非破坏地保存循环等 CFG 变体，并在最后全局抽取低成本方案。

> 本文主要研究：如何把等式饱和的“保留多个等价版本”思想从表达式扩展到受限控制流图。

## 3. 核心方法概述

E-Path 是 E-Sequence 的单调集合。E-Sequence 是从 CFG 派生的基本块序列；分支通过参数化 terminator 指向后继区域，merge block 划定序列边界。每条外部已验证规则把旧序列变成新序列，但不删除旧版本。

```text
受限 ANF CFG
→ 识别 E-Sequence（路径/结构化区域）
→ 结构匹配与控制流匹配
→ 外部已验证规则生成新 E-Sequence
→ hash-consing 去重并加入 E-Path
→ 固定点后计算每个序列的符号成本
→ 选择最低成本 CFG 变体
```

## 4. 实验框架与训练流程

本文不涉及模型训练。原型实现于 Crabstar 编译器后端的 Rust 代码，IR 为受限 A-Normal Form：每个基本块只有一条指令与一个参数化控制流终结操作。正文用 Loop-Invariant Code Motion（LICM，循环不变量外提）说明三步重写：检测环、依赖分析验证不变量、重建带 preheader 的新序列（第 3.1 节）。

## 5. 奖励函数、损失函数或关键公式

本文没有强化学习奖励函数。循环符号成本为：

```text
C = N * M
```

其中 `N` 是符号迭代次数，`M` 是循环体聚合成本；序列成本通过基本块求和与循环缩放组合，最终选择 `argmin C(S)`（第 6 节）。论文未给出真实硬件代价、分支概率或缓存模型。

## 6. 实验设置

论文中没有数据集、基线、硬件环境、运行次数或定量实验。当前实现支持无环指令序列和可约循环；表达式级匹配利用 ANF 显式依赖，控制流匹配依据 CFG 拓扑（第 7 节）。

## 7. 实验结果与结论

论文没有报告性能、内存、编译时间、代码质量或与 e-graph/RVSDG/传统 LICM 的实证对比，因此不能声称 E-Path 已降低 phase-ordering 代价或已扩展到大型 CFG。正文能确认的结果仅是：作者实现了 Rust 原型，并用 LICM 展示如何在保留原 CFG 版本的同时加入新序列（第 3、8 节）。

## 8. 主要创新点

### 8.1 以指令序列而非表达式为等价单位

E-Sequence 试图在保留 CFG 拓扑语义的情况下表示控制流区域。

### 8.2 CFG 变体的单调持久化搜索空间

每次重写只添加候选，使多个控制流组织能同时参与最终抽取。

### 8.3 用外部验证规则隔离正确性责任

E-Path 不内部推导等价性；结构只保存由已验证规则引入的关系，明确了数据结构与证明系统的边界。

## 9. 局限性

论文第 10 节明确说明：仅支持可约控制流，不建模 alias、内存效应或投机执行；不内部验证语义保持。单调集合可能无界增长，目前仅用结构哈希去重；所谓“给定重写闭包后有限”不能替代实际可伸缩性评测。PDF 仍含会议/DOI 模板，论文成熟度较低。没有条件分支、jump table、不可约循环、完整证明和任何定量实验。

## 10. 阅读后的研究方向反思

E-Path 提出的是表示假设，不是已经验证的优化系统。它对 LLVM/RISC-V 的潜在价值在于把循环变换、CFG pass 和后端成本放进同一非破坏搜索空间；但直接移植到 LLVM IR 会立即遇到内存模型、异常、未定义行为、alias 与代码爆炸。后续研究首先要证明“表示正确且能压缩共享结构”，其次才是 LLM 或硬件反馈。

## 11. 可进一步尝试的研究方向

### 11.1 带翻译验证的 CFG 等价搜索

#### 研究问题

能否让每次 E-Sequence 重写携带可检查证明，并对内存/循环做有界翻译验证。

#### 与原论文的区别

原文假设外部规则正确；新方向把证明生成、失败记录和抽取合法性纳入系统。

#### 可能的创新点

CFG 区域证明对象、内存 effect 摘要、失败规则隔离、证明感知抽取。

#### 实验框架

```text
小型 SSA CFG → LICM/分支简化候选
→ SMT/Alive2 风格区域验证
→ 只把通过候选加入 E-Path
→ 比较固定 pass 与全局抽取
```

#### 可行性与风险

可先限制为无别名整数循环；主要风险是循环语义、路径爆炸和验证器覆盖范围。

## 12. 与其他已读文献的关系

与 C16 Foresight 都强调非破坏重写，但 Foresight 仍以 e-graph/e-class 为核心并已做性能评测，E-Path 转向 CFG 序列且仍为原型；与 Alive2/翻译验证工作互补，可由验证器承担外部规则正确性；与 Protean 的 phase ordering 相比，E-Path试图把不同 CFG pass 结果同时保留；与 C17 EggMind 的策略合成结合前，必须先解决 E-Path 可伸缩性和正确性证据。
