## 1. 研究背景

机器学习工作负载大量使用张量收缩。张量领域专用语言（Domain-Specific Language，DSL）可以利用领域知识、硬件特性和厂商库生成高性能代码，但已有 C 等通用语言编写的程序不能直接获得这些优化。将旧程序自动提升（lifting）到张量 DSL 因而是编译器与程序综合问题。

传统程序综合能够提供较强的等价性保证，但在多维张量工作负载上搜索成本高，通常依赖针对特定 DSL 的手写启发式。LLM 能快速给出候选翻译，却可能不准确。论文的动机是把 LLM 的搜索空间建议能力与程序综合的验证能力结合起来。

## 2. 论文要解决的问题

### 2.1 如何自动生成等价的 TACO 程序

给定低层 C 程序 `p_s`，系统需要寻找 TACO 张量表达式 `p_t`，使其满足对所有输入的等价关系：`∀x. p_s(x) = p_t(x)`（第2节）。

### 2.2 如何在不依赖手写启发式的情况下控制搜索规模

完整 TACO 文法过大，直接枚举难以扩展；已有方法的手写剪枝又限制了覆盖率和可迁移性。论文研究如何从 LLM 候选中学习概率文法，并用它指导综合搜索。

### 2.3 如何兼顾候选覆盖率与正确性

LLM 候选只能作为搜索线索，不能直接作为最终结果。系统需要先用输入输出样例筛选，再用有界模型检查验证 C 程序和 TACO 程序的等价性。

> 本文主要研究：如何利用 LLM 学习张量 DSL 搜索启发式，并通过枚举综合与有界验证自动完成低层张量代码到 TACO 的等价提升。

## 3. 核心方法概述

论文提出 STAGG（Synthesis of Tensor Algebra Guided by Grammars）。它要求 LLM 为输入 C 程序生成约 10 个 TACO 候选，将候选归一化为模板并统计为概率上下文无关文法（pCFG），随后用两种 A* 风格的枚举搜索查找可行模板；通过输入输出测试和 CBMC 有界模型检查确认候选。

```text
输入 C 张量程序
        ↓
LLM 生成候选 TACO 表达式
        ↓
AST 解析、张量模板化、索引标准化、常量模板化
        ↓
构造概率上下文无关文法
        ↓
Top-down A* 或 Bottom-up A* 搜索模板
        ↓
输入输出样例验证具体替换
        ↓
TACO 编译、生成 C、CBMC 有界等价验证
        ↓
失败则继续搜索，成功则输出 TACO 程序
```

LLM 只负责提出搜索空间的候选结构；程序综合器负责系统枚举，验证器负责正确性检查。论文不把 LLM 的直接输出当作已验证的翻译。

## 4. 实验框架与训练流程

### 4.1 候选生成

论文使用提示词要求 LLM 只返回输入 C 程序对应的 10 个 TACO 表达式，温度设置为 1.0；系统解析实际返回的候选，并丢弃语法错误项。论文中未明确说明一个可训练的 LLM 微调流程，因此本文不涉及 SFT 或强化学习训练。

### 4.2 文法学习与搜索

系统把候选解析为 AST，依次进行张量名模板化、索引标准化和常量模板化，把结构相似但表面写法不同的候选归并到模板。模板中的产生式按候选出现频率赋权，再归一化成 pCFG。之后使用 top-down A* 和 bottom-up A* 两种枚举算法。

### 4.3 验证与反馈

完整模板先通过随机生成的输入输出样例进行具体替换验证；通过后编译为 C，并由扩展后的 CBMC 检查有界输入范围内的等价性。验证失败时系统回到搜索阶段，不把失败候选作为结果。

## 5. 奖励函数、损失函数或关键公式

本文没有使用强化学习奖励函数或神经网络损失函数。搜索使用以下代价：

```text
c(x) = Σ[-log2 P(r_i)]
f(x) = c(x) + g(x) + X(x)
```

其中 `c(x)` 是从根节点到当前部分表达式所用产生式的累积代价；`P(r_i)` 是产生式概率；`g(x)` 估计完成剩余非终结符所需的最小附加代价；`X(x)` 是违反领域约束的惩罚。文中列出 5 类约束，包括维度列表长度、张量符号顺序和不合理结构等，部分违规使用无限惩罚。该目标用于优先搜索高概率且满足 TACO 语法约束的模板，不是训练目标。

## 6. 实验设置

### 6.1 数据集来源

评测集包含 10 个人工示例和 67 个真实世界问题，共 77 个；真实问题中 61 个来自已有代码库，6 个来自 Llama 的 C++ 推理代码。论文以 TACO 的密集张量表达式为目标，输入是低层 C 程序。论文没有给出传统意义上的训练/验证/测试集划分，因为系统不训练模型。

### 6.2 模型与工具

系统使用 LLM 生成 TACO 候选；论文正文未明确给出该 LLM 的具体模型名称和参数规模。综合器使用扩展的 CBMC 6.3.1 和 cvc5 1.0.5；验证阶段将 TACO 降低为 C，并使用 CBMC 做有界模型检查。文中还描述了 JAX 将 NumPy 降低到 MLIR 的流程。

### 6.3 对比方法

主要比较对象包括直接 LLM 输出、C2TACO、去除 C2TACO 启发式的 C2TACO.NoHeuristics，以及 Tenspiler。STAGG 还比较 top-down 与 bottom-up 搜索、完整文法、等概率文法和 LLM 概率文法配置。

### 6.4 评价指标

| 指标 | 含义 |
|---|---|
| Solved benchmarks | 在评测集上找到并验证解的数量/比例，越大越好 |
| Solving time | 每个查询的综合时间，通常越小越好 |
| Coverage | 能成功提升的程序范围，越大越好 |
| Verification success | 候选是否通过 CBMC 有界等价检查 |

## 7. 实验结果与结论

### 7.1 主要结果

STAGG 在论文总结中对 77 个基准达到 99% 的提升成功率，平均提升时间为 3.19 秒。表格显示，STAGG top-down 在 77 个问题上解决 76 个，平均时间 106.13 秒；bottom-up 解决 73 个，平均时间 98.81 秒。两种配置的统计口径是 67 个真实问题加 10 个人工问题。

### 7.2 与传统综合器比较

在同一 77 项集合上，C2TACO 解决 67 个问题，平均时间 21.15 秒；Tenspiler 在其报告覆盖的 52 个问题上平均时间 4.56 秒。STAGG 的优势主要是覆盖率，而不是所有子集上的绝对时间最优。

### 7.3 与直接 LLM 输出比较

直接 LLM 输出只解决 34 个问题（表中真实世界+人工集合），说明 LLM 候选本身不能替代综合与验证。STAGG 通过候选结构归纳和系统搜索显著扩大了可验证覆盖范围。

### 7.4 消融实验

删除文法细化后，使用 LLM 概率的配置比完整 STAGG 少解决 31% 的基准。惩罚规则也有效：例如 top-down 删除规则 A 后解决数从 76 降到 71，删除 `a3` 后降到 72。论文还指出，学习到的概率如果放入过于宽泛或未充分细化的文法，可能带来负面影响。

### 7.5 案例与边界

Top-down 覆盖更多问题；bottom-up 在双方都能解决的常见问题上更快，但其只能通过追加方式扩展表达式，不能很好处理需要更平衡 AST 或括号结构的程序。论文将浮点等价转换为有理数数据类型进行验证，并没有声称这覆盖所有真实浮点语义。

## 8. 主要创新点

### 8.1 创新点一：用 LLM 学习综合搜索空间

论文不是直接让 LLM 输出最终代码，而是把多个候选归纳为概率文法，借此把 LLM 的启发式知识转成可搜索、可验证的结构。实验显示，概率文法和文法细化共同改善了覆盖率。

### 8.2 创新点二：两种面向模板的枚举搜索

STAGG 提出 top-down 和 bottom-up 两种 A* 风格搜索，将概率代价、剩余代价和领域惩罚结合起来。两者在覆盖率与求解时间之间有不同取舍。

### 8.3 创新点三：LLM 候选与形式化验证的分工

LLM 负责提出可能的结构，输入输出测试负责快速过滤，CBMC 负责有界等价检查。论文的价值不在“使用 LLM”本身，而在于把不可靠的候选生成放入可验证综合管线。

## 9. 局限性

### 9.1 论文明确展示的局限

论文只研究密集张量代码到 TACO 的提升，不代表对任意 DSL 或任意控制流程序都成立。bottom-up 搜索对平衡 AST 和括号结构存在限制。等价验证采用有界模型检查；论文没有把它表述为对所有无界输入的完整证明。

### 9.2 阅读后发现的潜在局限

候选质量依赖 LLM 提示和采样，模型名称、参数规模和调用成本在正文中未明确说明。验证依赖 C/CBMC 可表达的有界模型，复杂动态内存、未建模库函数或浮点环境可能影响适用性。跨到 RISC-V 或其他硬件时，主要挑战还包括 DSL 后端和性能模型迁移，这不是本文实验直接证明的结论。

## 10. 阅读后的研究方向反思

值得借鉴的是“LLM 提议搜索空间、编译器/验证器决定是否接受”的分工，以及把候选变成可统计的文法而非依赖一次生成。STAGG 已经把概率文法驱动的张量提升作为核心贡献，后续不能只把 TACO 换成 RVV intrinsic 就宣称创新。对本项目而言，它更适合作为多硬件编译中的候选生成与验证模块参考，而不是现成的 RISC-V 后端方案。

## 11. 可进一步尝试的研究方向

### 11.1 面向 RVV 的可验证张量提升

#### 研究问题

如何把 C/NumPy 张量表达式提升为带 RVV 向量语义的中间表示，并保持跨向量长度实现的等价性。

#### 与原论文的区别

目标从 TACO DSL 扩展为 RVV-aware IR，需处理 VLA 向量长度和尾部策略，而不是简单替换 DSL 名称。

#### 可能的创新点

学习 RVV 结构化候选文法、把向量长度约束加入搜索代价、用 LLVM/RVV 后端和等价检查联合验证。

#### 实验框架

```text
C/张量程序 → LLM 候选 RVV 结构 → 文法搜索 → LLVM/RVV lowering → 等价与真机性能验证
```

#### 可行性

需要 LLVM/RVV、CBMC 或 SMT 等价检查、RVV 模拟器或真机，以及密集线性代数基准。

#### 主要风险

有界验证可能无法覆盖向量长度变化；真机性能受微架构、访存和尾处理影响，不能仅用静态指令数代替。

### 11.2 编译器反馈驱动的概率文法更新

#### 研究问题

如何把编译时间、代码尺寸和硬件运行反馈用于更新候选文法，而不破坏语义验证约束。

#### 与原论文的区别

原论文主要用 LLM 响应频率学习文法；新方向加入跨硬件性能反馈和在线更新。

#### 可能的创新点

建立正确性硬门控下的多目标文法权重更新，并评估其在未见硬件上的迁移。

#### 实验框架

```text
候选文法 → 形式验证过滤 → 多硬件编译/运行 → 性能反馈 → 更新产生式权重
```

#### 可行性

可复用 STAGG 的搜索结构、LLVM/MLIR 的编译反馈和现有 CPU/RVV 测试平台。

#### 主要风险

真实运行噪声、硬件差异和权重更新可能使搜索不稳定；必须区分验证通过与性能变好的样本。

## 12. 与其他已读文献的关系

本批次中 C27 关注 LLVM IR 语义、未初始化内存和 Alive2 正确性；C28 关注 DSL 提升、枚举搜索和 CBMC 验证。C28 可作为 C27 所强调的“语义正确性基础设施”之上的应用型综合案例，但两者不直接共享算法。C28 更适合作为多硬件/张量编译的搜索方法参考，C27 更适合作为 IR 语义与验证基础设施参考。
