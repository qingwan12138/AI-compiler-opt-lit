## 1. 研究背景

LLM在IR级编译器优化中展现了巨大潜力，能够生成超越传统编译器的pass序列和代码变换。然而，LLM生成的IR代码面临两个致命问题：(1) 不可编译——LLM可能生成语法错误的IR，导致编译失败；(2) 语义等价性缺失——即使语法正确，LLM生成的变换可能改变程序行为（引入bug或undefined behavior）。传统监督学习或RL方法使用I/O测试（将原始IR与优化后IR在相同输入上运行并比较输出）来近似验证等价性，但I/O测试的覆盖率有限，缺乏严格的形式化语义保证——对于某些输入输出一致但内部语义不同的变换，I/O测试无法检测出问题。例如，一个变换可能在所有测试输入上输出正确结果但实际上改变了程序的某些边界行为。更严重的是，如果缺乏严格的验证机制，LLM在RL训练过程中可能学习到"在大多数常见情况下正确但特定条件下错误"的优化策略，这将带来严重的安全风险。因此，关键问题是如何将形式验证的严格反馈纳入LLM的强化学习训练过程，使模型同时学习"正确优化"和"有效优化"。

## 2. 论文要解决的问题

### 2.1 如何将Alive2验证输出转化为可训练的RL信号

Alive2的输出包括verified（语义等价）、refuted（语义不等价，附带反例）和inconclusive（超时或超出Alive2支持范围）三种状态，每种状态需要不同的奖励映射策略。需要设计一个奖励函数，能够正确反映不同验证结果的安全含义——对"refuted"的惩罚需要足够大以防止模型学习不安全变换，但对"inconclusive"的处理需要谨慎，因为超时并不等价于语义不等价。此外，Alive2的诊断反馈（如具体违反的语义条件、触发未定义行为的位置）需要被有效利用来指导模型自修正。

### 2.2 如何平衡安全性和有效性

需要设计训练策略，使得LLM既学会避免产生语义错误的变换（安全性），又学会发现性能更优的变换（有效性），同时不牺牲多样性——安全性和有效性之间存在张力：过于注重安全性可能导致模型只生成简单保守的变换（如恒等变换），从而失去优化价值；过于注重有效性可能导致模型频繁生成高风险的激进变换。

### 2.3 小模型能否通过验证引导RL达到大模型水平的优化效果

需要验证在小规模模型（Qwen-3B）上通过验证引导的RL能否取得能与大规模模型甚至手写编译器Pass竞争的优化效果。核心假设是验证反馈可以作为模型能力"放大器"，使小模型通过强监督信号达到接近大模型的优化水平。如果验证有效，那将意味着编译器优化领域的LLM应用不必依赖最大规模的商业模型，可以用开源小模型加验证引导达到可接受的性能水平。

> 本文主要研究：如何将Alive2形式验证的反馈作为GRPO强化学习的奖励信号，通过三阶段训练策略使小型LLM（3B）在IR级编译优化中同时实现高正确率（约90%）和高性能（2.3x加速）。

## 3. 核心方法概述

LLM-VeriOpt将Alive2的验证结果直接整合进GRPO（Group Relative Policy Optimization）的奖励函数中。核心思路是：对于LLM生成的每个IR变换候选，先用Alive2进行语义等价性检查——如果Alive2判定为等价（verified），则给予正奖励并进入后续性能评估；如果判定不等价（refutation）或无法判定（inconclusive如超时），则根据错误类型提供差异化负奖励。同时，Alive2的诊断输出（如具体违反的语义条件、触发UB的位置）被加入训练样本的prompt中，作为LLM自修正的指示信号。训练分为三个阶段，逐步从"学会安全"过渡到"学会高效"。

```
输入LLVM IR函数
        ↓
Qwen-3B LLM生成IR变换候选（group=8个候选）
        ↓
每个候选用Alive2验证语义等价性
        ↓
   ┌──verified ──→ 性能评估（指令数/代码尺寸）
   ├──refuted ──→ 提取反例信息加入训练样本
   └──inconclusive ──→ 赋低奖励（非惩罚）
        ↓
GRPO训练（组内排序 -> 更新模型参数）
        ↓
三阶段循环（诊断生成 -> 正确性训练 -> 延迟优化）
```

## 4. 实验框架与训练流程

### 4.1 IR变换生成器

使用Qwen-3B作为base LLM，给定LLVM IR函数作为输入，生成优化后的IR代码。输入格式为LLVM IR的文本序列，模型输出也是IR文本，通过Pass工具（如opt）验证语法的正确性。模型在C4和LLVM IR混合数据上进行了继续预训练。

### 4.2 Alive2验证器

对每一对输入IR和输出IR，Alive2在bounded范围内（有界循环展开、有限函数内联等约束下）进行语义等价性验证。输出可能为verified（语义等价）、refuted（语义不等价，附带反例）或inconclusive（超时或超出Alive2支持范围）。验证超时设置为30秒，超过则认为inconclusive。Alive2的诊断输出（如"poison传播不一致"、"内存访问越界"等）被结构化地加入训练样本的prompt中。

### 4.3 GRPO训练框架

GRPO不需要value/critic模型，直接从group内样本的相对表现构造优势函数。具体来说，对同一个prompt采样多个IR变换（group size=8），各组内的Alive2验证结果和运行时性能作为排序依据，更新LLM参数以提升最优样本的生成概率。GRPO相比PPO的优势在于：(a) 不需要额外的critic模型，节省了训练内存；(b) 组内归一化使得奖励设计更灵活；(c) 与验证反馈的离散性（通过/失败）更加兼容。这使得GRPO非常适合于编译器优化这种离散反馈场景。

### 4.4 三阶段训练策略

**阶段一：诊断增强样本生成。** 使用LLM生成多样化的IR变换候选，并用Alive2诊断信息标注错误原因（如"poison传播不一致"、"内存访问越界"等）。此阶段产出的数据用于GRPO训练的初始种子。这一阶段的目标是产生一个覆盖广泛错误类型的诊断标注数据集，供后续阶段使用。

**阶段二：正确性导向训练。** 在GRPO中重点强调验证通过率，大幅惩罚验证失败的变换。奖励设计为：verified=+1.0，refuted=-1.0，inconclusive=-0.5。此阶段目标是使模型的验证通过率达到90%以上。该阶段优先确保安全性，即使暂时牺牲性能也在所不惜。

**阶段三：延迟优化。** 在模型正确率达标后（约90%），逐步引入性能指标（代码尺寸、指令数、编译时间）作为辅助奖励信号，引导模型在保持正确性的前提下优化性能。奖励公式为 `reward = w1 * correctness + w2 * performance`，其中w1=0.6, w2=0.4。该阶段的挑战是如何在引入性能优化信号的同时不破坏前期建立的正确性保证。

## 5. 奖励函数、损失函数或关键公式

| 符号 | 含义 |
|---|---|
| verified | Alive2判定输入和输出IR语义等价 |
| refuted | Alive2判定语义不等价（附带反例counterexample） |
| inconclusive | Alive2超时（30s）或超出支持范围 |
| group_size | GRPO组内采样数，设置为8 |
| w1, w2 | 阶段三奖励权重，w1=0.6, w2=0.4 |
| verif_rate | 验证通过率（verified / total candidates） |
| perf_gain | 指令数减少比例或运行时间加速比 |

阶段二奖励函数：
```
R = +1.0  (if verified)
R = -1.0  (if refuted)
R = -0.5  (if inconclusive)
```

阶段三复合奖励函数：
```
R = w1 * R_verif + w2 * R_perf
  其中 R_verif = +1.0 (verified), -1.0 (refuted), -0.5 (inconclusive)
      R_perf = normalized performance gain (e.g., instruction count reduction)
```

GRPO的优势函数（组内归一化）：
```
A_i = (R_i - mean(R_group)) / std(R_group)
```

GRPO的策略梯度更新（无critic模型）：
```
∇J(θ) = E[Σt ∇log πθ(at|st) * A_i]
```

## 6. 实验设置

### 6.1 数据集来源

使用LLVM测试套件和开源C/C++项目编译产生的IR作为训练和评估数据。具体包括LLVM自带的测试集（如SingleSource、MultiSource测试套件）以及从GitHub上收集的开源C/C++项目编译后的IR。训练集和测试集严格分离，确保测试程序在训练阶段未被模型看到。

### 6.2 模型与工具

基础模型为Qwen-3B，在C4和LLVM IR混合数据上进行了继续预训练。验证工具为Alive2。编译工具链为LLVM/Clang。训练框架支持GRPO算法实现。验证超时设置为30秒。

### 6.3 对比方法

对比基线包括：基础Qwen-3B（零样本直接生成IR变换）、监督微调版Qwen-3B（使用正确变换示例微调，约50K样本）、LLM-VeriOpt不使用GRPO（仅监督学习，同监督微调但数据含诊断信息）、传统优化基线（LLVM O2/O3、手动编写的instcombine变换）、LLM-Vectorizer（在适用子集上对比）。

### 6.4 评价指标

评价指标分为三个维度：正确性指标——Alive2验证通过率（verified %）、编译成功率（syntax-valid %）；性能指标——生成的输出IR相对O0的指令数减少、运行时间加速比（在x86-64上实测）；创新能力指标——成功修改代码数量（即生成的IR与输入IR不同且验证通过）、超出instcombine覆盖范围的优化数量。

## 7. 实验结果与结论

### 7.1 主要结果

正确性方面：LLM-VeriOpt生成的可验证输出达到约90%（Alive2 verified），远高于基础Qwen-3B的约30%，也显著高于监督微调后的约60%。验证引导的RL比监督微调在正确性上多提升约30个百分点。性能方面：相对O0，LLM-VeriOpt实现了约2.3x的加速（指令数减少等效），部分案例接近甚至超过手写instcombine的效果。在子集上对比LLVM O3，达到约80%的竞争性能。创新能力方面：成功修改代码数量相对基础Qwen-3B提升约5.4倍，表明验证引导的训练不仅提高了正确性，还激发了模型生成更多非平凡的优化变换——模型从"几乎不改动"变为"积极尝试变换并保证正确"。

### 7.2 消融实验

三阶段训练策略中的每个阶段都对最终结果有正向贡献：正确性导向训练阶段贡献最大（使验证通过率从60%提升至85%），延迟优化阶段进一步改善了性能（在保持90%通过率的前提下性能提升15%）。消融实验还比较了不同group size对GRPO效果的影响——group size=8时效果最优，过小（2-4）导致优势估计不准确，过大（16+）导致训练效率下降。比较了不同奖励设计（仅正确性奖励 vs 复合奖励）——复合奖励在保持正确率的同时获得更好的性能。

### 7.3 案例分析

论文对具体的IR变换案例进行了分析，展示了模型如何在验证反馈的指导下从错误的变换逐步修正为正确的变换。一个典型案例是常量折叠场景：初始模型生成的变换导致poison值传播方式不一致（Alive2判定refuted），通过将反例信息注入prompt，模型在下一轮尝试中成功避免了这个错误路径。这证明了验证反馈作为训练信号而非仅后处理过滤器的优势——模型不仅学会"不做错的变换"，还学会"理解为什么错并尝试做对的变换"。

## 8. 主要创新点

### 8.1 创新点一：验证反馈作为GRPO训练信号

首次将Alive2的形式验证反馈直接作为GRPO强化学习的奖励信号，将"语义等价性"从后处理过滤器转化为训练信号。这一范式转变使得模型能够在训练过程中主动学习避免错误变换，而不是在推理后被动过滤。这是"训练时验证"优于"推理后过滤"的关键证据。

### 8.2 创新点二：三阶段递增难度的训练策略

提出了三阶段训练策略（诊断生成-正确性导向训练-延迟优化），循序渐进地将LLM从"学会语法正确"引导到"学会语义正确"再到"学会性能高效"。这种分阶段递增难度的训练方法不仅在编译器优化领域具有普适性，也符合课程学习（curriculum learning）的理论框架——先学简单任务再学复杂任务。

### 8.3 创新点三：小模型+强验证信号弥补模型规模不足

在小型模型（3B）上通过验证引导的RL实现了接近/超过手写编译器Pass的优化效果，展示了验证引导训练对提升模型能力的显著效果。这一发现对于实际部署具有重要意义——不必依赖最大规模的商业模型即可获得可接受的优化水平，降低了LLM在编译优化中的应用成本和依赖风险。

### 8.4 创新点四：Alive2诊断反馈的循环利用

Alive2诊断反馈的循环利用——将验证错误信息加入prompt指导LLM自修正，形成闭环改进。模型在看到"Alive2 refuted: poison propagation mismatch at line 42"等诊断信息后，可以在下一轮尝试中修正错误。这种将验证诊断作为可学习信号的方法显著加速了模型的正确性学习过程。

### 8.5 创新点五：GRPO在编译器优化中的成功应用

验证了无critic模型的RL算法（GRPO）在离散反馈（通过/失败）场景中的有效性，相对PPO更节省显存，且收敛稳定性更好。GRPO的组内归一化特性与验证结果的离散性质高度契合，为编译器优化中的RL应用提供了算法选择参考。

## 9. 局限性

**论文明确承认的局限：**
(1) Alive2是有界验证器——对于循环需要展开（有界），不支持所有LLVM特性（如间接跳转、异常处理），超时或被错误标记为inconclusive的变换可能实际上是正确的但被系统拒绝。这导致约10%的inconclusive结果可能包含正确变换但被丢弃。
(2) 验证仅在LLVM IR层面进行，不包含后续后端代码生成阶段的语义等价检查——一个在IR层等价的变换可能在后端代码生成中引入错误（如寄存器分配错误导致的语义变化）。IR层等价性不等于最终二进制代码的等价性。
(3) 实验中的性能信号主要使用指令数或代码尺寸作为代理指标，没有直接将真实目标平台（具体CPU）上的运行时间作为训练信号——这意味着模型优化的是IR层指标而非实际运行性能。

**阅读后发现的潜在局限：**
(4) 没有跨架构实验（如RISC-V、ARM），验证和性能优化都是针对x86-64的LLVM IR。模型是否能为RISC-V生成同样正确且高效的变换未经测试。指令数减少在不同架构上的性能影响可能差异显著。
(5) 只有3B模型的实验，更大规模模型上的效果未知——验证引导的训练是否能在7B、13B或70B模型上产生更显著的提升未被探索。理论上，大模型的生成多样性和推理能力可能受益于验证引导更多。
(6) 验证反馈可以解决"能不能安全做"，但还没有解决"在不同硬件上是否值得做"——同一个IR变换在x86上可能性能提升但在RISC-V上可能性能下降，LLM-VeriOpt的奖励信号无法区分这种情况。这是从"单架构正确优化"到"多架构条件优化"的核心鸿沟。

## 10. 阅读后的研究方向反思

【分析内容】LLM-VeriOpt是后续研究必须采用和超越的正确性底座。IR Agent的任何优化动作都应先通过Alive2语义门控（验证），未通过的动作不得进入后端性能评估——这是确保优化安全性的最低要求。LLM-VeriOpt证明了验证作为训练信号而非仅后处理过滤器的有效性。三阶段训练策略（安全-正确-高效）可以直接适配到双智能体的IR Agent训练流程中——第一阶段让模型学会生成语法和语义正确的IR，第二阶段引入性能优化。验证反馈解决了优化可行性问题，但需要后端性能反馈来解决优化价值问题——这正是核心创新空间：在验证门控之上引入跨架构后端性能信号。将验证结果与后端性能结合作为联合奖励信号是一个自然的技术延伸：验证保证正确性，后端评测保证性能，两者互补。验证反馈本身是架构无关的——Alive2对任何LLVM IR变换都可操作——而性能反馈是架构相关的，这构成了跨架构学习的核心张力。LLM-VeriOpt对GRPO的成功应用为RL训练提供了算法选择参考——验证反馈的离散性（0/1）适合GRPO的组内排序范式。

## 11. 可进一步尝试的研究方向

### 11.1 验证引导的跨架构联合RL训练

#### 研究问题
如何将LLM-VeriOpt的验证引导RL扩展到多架构场景，使LLM学会同时为x86-64和RISC-V生成正确且高效的IR变换？

#### 与原论文的区别
原论文仅针对x86-64的IR级优化，新方向引入跨架构性能信号作为辅助奖励，使模型学会区分"一个变换在不同架构上的差异化效果"。

#### 可能的创新点
架构感知的条件化GRPO训练（将目标架构信息作为条件输入）、跨架构奖励函数设计（验证奖励+架构特定性能奖励）、架构对比学习（同一变换在x86和RISC-V上的性能差异作为对比学习信号）。

#### 实验框架
在x86-64上训练基线版本，然后在RISC-V上微调架构特定版本，比较单独训练和联合训练的效果。

#### 可行性
高，基于LLM-VeriOpt现有框架增加架构维度，技术上可行。

#### 主要风险
跨架构训练数据获取成本高（需要双平台硬件评测），模型可能过拟合到特定架构。

## 12. 与其他已读文献的关系

【分析内容】LLM-VeriOpt在三篇聚焦论文中具有最深的RL方法论贡献，是整个文献阅读集合中的"正确性底座"。与ReasoningCompiler的关系：ReasoningCompiler缺乏正确性验证，LLM-VeriOpt提供了将验证嵌入训练过程的标准方案——两者结合可以实现"既高效搜索又保证正确"。与ACCLAIM的关系：ACCLAIM使用验证作为后处理过滤器（推理时验证），而LLM-VeriOpt使用验证作为训练信号（训练时验证），后者的范式更根本地改变了模型行为。与综述（Paper 9）的关系：LLM-VeriOpt恰好填补了综述识别的一个重要空白——"验证引导的generator类方法"，且其成功证实了综述对验证引导方向的积极判断。对于后续研究，LLM-VeriOpt的验证引导RL可以作为IR Agent的训练方法论，而其跨架构缺失点正是新框架的核心创新空间——验证提供"能否安全做"的保证，跨架构后端反馈提供"在特定架构上是否值得做"的指导。

## 13. 一页式总结

| 项目 | 内容 |
|---|---|
| 论文研究任务 | 验证引导的强化学习用于LLM-based IR级编译优化 |
| 核心问题 | 如何将形式验证反馈嵌入RL训练使模型兼顾安全性和有效性 |
| 核心方法 | Alive2验证反馈作为GRPO奖励信号 + 三阶段训练策略 |
| 使用模型 | Qwen-3B |

| 是否使用形式验证 | 是（Alive2进行IR级语义等价性验证） |

| 与RISC-V相关性 | 中 |

> LLM-VeriOpt通过将Alive2验证反馈作为GRPO奖励信号进行三阶段训练，在3B模型上实现约90%验证通过率和2.3x加速，但仅覆盖LLVM IR层面正确性且缺乏跨架构性能信号的引入——这一局限性正是后续跨架构编译优化研究（如验证门控+跨架构后端性能信号结合）可以直接接力的技术空白。
