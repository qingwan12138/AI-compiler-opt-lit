# SalvageIR 正式实验路线

> salvageir_v3 · 2026-09-21。P0详见PILOT_PROTOCOL；本文件规划P1/P2，不授权启动。

## 1. 三个必须分开的实验

1. 现象实验：表示内是否存在有益严格子集？用oracle/witness，不依赖主算法能否找出。
2. 机制实验：固定表示与候选，反例引导是否提高预算效率？
3. 系统实验：在所有预定源程序上，加入回收后是否比accept-or-fallback和强基线增加真实收益？

PRE_SSA主轨与POST_OZ补充轨分层报告。它们共用源码身份，不共享初始候选。
不要把POST_OZ失败池更少直接写成PRE_SSA更好；全源配对端到端比较才回答完整流程收益。

## 2. P1基线定义

所有非LLM方法共享composer/H、源/目标公共验证、精确成本、两道接纳证明和预算记账。

| ID | 方法 | 具体限制 |
|---|---|---|
| B0 | 丢弃失败候选，回退P(X) | 端到端最低基线 |
| B1 | 同模型无反馈整函数重采样 | 同源prompt，每请求独立上下文，最多2次新增请求 |
| B2 | 同模型整函数修复 | 提供原输入、失败目标与原始Alive2诊断，最多2次新增请求 |
| B3 | 文本hunk回滚 | 固定diff算法；不借用语义图，非法输出照计资源；仅弱基线 |
| B4 | 随机结构掩码 | 采样Bernoulli(0.5)掩码后按固定硬蕴含修正，重复也记proposal成本 |
| B5 | 无切片best-first | 主算法动态/静态分数全置0，其余完全相同 |
| B6 | 结构hierarchical-ddmin | 按稳定组件序，层次分组删/保留；逐轮记录所有候选，不在首个正确时退出 |
| B7 | 反例软命中诊断 | 在同一冻结组件空间内，MaxSAT/ILP最大化当前状态切片覆盖、再最小化翻转数 |
| M | SalvageIR | ALGORITHM_SPEC的冻结排序 |
| O | 表示相对穷举 | 只对完成枚举的表示报告精确最优；不参与同预算胜负 |

B6先尝试保留/撤销连续组件块，划分从2组逐次加倍到单组件；结构闭包后去重；
遇VERIFIED状态保留其精确成本，随后按稳定ID尝试单组件加回及闭包，直至无新状态或预算到达。
允许跳过不合法组合，不将语义正确性当单调属性；全源正确不能算成功。
为了避免实现稻草人，开发阶段同时测试从源加回与从目标回滚版本，在开发集冻结较强者。
B7的切片仅为软目标，不把“至少撤销一个命中组件”当全局必要条件。
B7与M使用同一可信CE适配器和结构合法性约束，但B7可以提出非局部掩码，不能人为限制成M的单步邻居。
B7从全目标开始，以当前已评估状态的反例切片为软目标；字典序先最大软覆盖、再最少翻转、再稳定掩码ID。
枚举不同诊断时只阻断已提议的具体掩码；新状态反例不变成跨状态永久硬约束。
每得到一个VERIFIED状态，按B6相同的确定性加回过程改善利润，再继续诊断队列；全源不计成功。
求解CPU时间计入预算，不能用oracle答案当软标签；求解超时是预算失败而不是反例。
B1/B2的内容上限和额外LLM时间/费用全计入，无法在时间预算内返回就记未成功。
不要求B1/B2与M“LLM调用次数相同”；给相同资源上限及Pareto曲线，而非抹平零调用优势。

## 3. 消融：只改变一个因素

- StaticOnly：动态反例键置0，静态信息保留。
- MatchedRandom：同一父状态、同一方向与依赖度桶内置换分数，固定种子17/29/43，逐种子和平均结果都报告。
- NoReAdd：移除加回操作，检验从安全状态恢复利润的价值。
- RepresentationCoarse：主动粗化表示，只用于表示覆盖分析，不叫纯搜索消融。
- TextOnly：B3，与结构表示比较；不能作为唯一强基线。
- ProxyOnly：仅以IR减少排序，但最终仍执行两道验证和精确成本，禁止输出不安全结果。

MatchedRandom置换不足时报告可置换比例；不能据单元素桶未改变的安慰剂作反例因果结论。
无需跨函数错配witness，因为那会引入不合法映射混淆。
若自动动态witness仅覆盖很少候选，主结果仍包括其余候选；定位子集结果只能是条件分析。

## 4. 预算与运行器

P1开发默认沿用P0参数，验证截点16/32/64/128。
若增加256-call曲线，必须同步提升状态/成本/墙钟预算并另锁配置；不能仅增加横轴。
所有Alive2调用，包括X→Oz(R)，消耗同一验证预算；同一hash证明可在方法内部缓存。
预算曲线只读该预算完成时的incumbent，禁止后看更多状态再回填早期结果。
精确成本失败、UNKNOWN与未完成都在方法分母中计未成功。
另报告相同wall-clock和总费用视图；费用按CPU/GPU/服务实际单价单列，不把本地CPU视为免费。
图构建、反例物化、求解和队列维护都计端到端时间。
同空间方法的共享预处理时间可以单列，但需要计入系统总成本。
不只汇报共同成功样本的速度；未成功样本的time-to-first-useful按预算右删失。

## 5. P2数据与模型冻结

P0b不是正式确认集。P1结束后，独立建立未触碰项目组和模型清单。
主PRE_SSA确认集必须来自有未优化出处的IR或可复现源码；LLVM nightly已优化数据只能作为POST_OZ补充。
同源、镜像、近重复族跨项目也必须同组；确认前运行源级去重，不看模型输出。
至少三模型家族，其中至少一个未参与prompt/表示/搜索调试；有可获取的较强模型，避免只研究旧小模型错误。
不要求各模型恰好产生某个数量的错误，不按失败率换模型；失败稀少就是实用性结果。

正式样本数不能从当前2/32推断。P1开发后执行并存档：
1. 选择预算内最强B5/B6/B7为Bstar，按端到端增量排序，平局按较少时间、再ID；随后冻结。
2. 主最小关注差异默认为全源端到端成功率1个百分点（工程投资标准，不是领域事实）。
3. 在项目数24/48/96/192、每项目4函数的网格上，用开发配对结果估计稀疏性、项目相关性，保守模拟2000次。
4. 选择能够达到80%规划功效且实际资源允许的最小格；保存生成模型、种子和敏感性。模拟不可靠则不宣称功效充分。
5. 真实N、项目名单、模型、Bstar、差异阈值、预算、分析脚本全部写入formal.lock，才打开确认候选。
6. 网格上限仍不足或资源不允许则确认阶段未就绪；不降低效果阈值假装已规划完成。

该步骤需P1数据才能执行，目前formal.lock尚未生成；这是明确的阶段依赖，不是已有实验。
新数据固定样本，不按p值或恢复成功率提前停/无限扩样。

## 6. 主要终点与统计

主终点：PRE_SSA下每个冻结source×model首次生成，经相应方法得到有益最终程序的二元结果。
所有初始正确有益输出对各恢复方法相同；其他未成功槽位回退计0。
M−Bstar的配对端到端成功率差，是主要效果；核心失败条件恢复率是必报机制指标，不替代端到端。

五个预声明比较：M−B5、M−B6、M−B7、M−StaticOnly、M−MatchedRandom。
以项目/镜像/近重复连通组为顶层簇，配对bootstrap 10000次，seed=20260921；
每次选取整个簇的全部函数、模型、设置及方法记录，保持相关性；模型先等权，函数在模型内按预定权重。
给点估计、普通95%区间，并为五比较给Bonferroni两侧99% percentile区间（0.5%/99.5%分位）。
这是近似bootstrap推断，不宣称有限样本严格覆盖保证；不再混用“Holm调整bootstrap simultaneous CI”。
项目数少于24、结果极稀疏或重采样分布退化时，报告计数和敏感性，正式推断标INCONCLUSIVE，不用全零区间背书。
做leave-one-project-group-out与项目贡献集中度审计；移除一个簇即改变结论则注明不稳健。
源码项目不是独立随机总体样本，推断范围限冻结benchmark抽样框，不外推互联网代码。

允许主张：
- Bstar比较校正区间下界>0且点差达到冻结工程标准：支持相对该强基线的实际增量。
- 声称超过全部强结构基线：三个对应校正区间均>0；不能只挑最弱者。
- 声称动态反例增量：StaticOnly和MatchedRandom比较均支持正向，且安慰剂确实改变排序。
- 区间跨0：证据不足，不自动宣布两方法等效；等效需另行预声明等效界/设计。

次要量：候选条件率、全部REFUTED覆盖率、已知可回收下界、对象字节收益、总时间/费用、
非法状态、未知状态、图大小、coarse比例、后Oz收益消失率、完整oracle相对regret。
oracle未完成不计算精确regret。多次输出的后续best-of-k分析另注册，不替换首次输出主终点。

## 7. 完整程序集与RISC-V

在方法冻结后，从同一锁定LLVM test-suite源码选择有参考输出且两平台可构建的程序集。
先定样本名单，再运行优化；不要为了成本校准提前查看此保留集。
P0成本校准仅用工程fixture/开发源码，不接触正式程序集。

为每个程序保存baseline完整构建与候选替换构建：
- 只替换直接验证通过的函数，保留原模块上下文/链接属性；
- 多函数替换逐项留证据，并跑完整程序参考输出；
- 记录LTO/ICF/链接器/relaxation flags，主比较两边相同；
- 测链接后code+rodata及alloc_non_bss；不把函数ST_Size之和冒充最终尺寸；
- 所有预定程序均进分母，无法优化回退零收益；测试错误属于系统失败，不静默删掉。

RISC-V默认只做RV64GC，ABI lp64d；从同源独立编译原始IR，不改x86 triple/datalayout。
冻结算法、prompt模板、模型与预算，只按目标填写metadata并替换目标成本。
独立生成T0_rv及执行X_rv→R_rv、X_rv→Oz(R_rv)，x86证明不能沿用。
测的是冻结方法重跑，不是同一掩码零样本迁移；跨目标编辑投影、RVV和AArch64暂缓。
QEMU可辅助参考输出检查，不用QEMU时间声称真机加速。
RISC-V需报告全部预定程序的收益、失败和区间；仅成功案例不足以声称总体提升。

## 8. 复现包

必须包含锁、许可证、源/候选manifest、可再分发原始IR/日志、组件图和每状态trace、
精确命令、后端对象hash、分析代码/测试、失败与偏差日志、一小组可离线重放案例。
不上传受限权重或未获许可源码；提供获取方式与hash。
证明、实现、数据、分析四类版本都能从最终表格追溯，不靠自然语言汇报替代。
