# SalvageIR 第一轮严苛审稿意见

> 评审对象：Git 提交 `68d6644` 对应的框架版本。
> 目标 venue 视角：CGO / PLDI / ASPLOS 主会。
> 评审原则：先寻找足以拒稿的原因，不把未来可能实现的功能当作已有贡献。

## 1. 总评与裁决

**建议：Weak Reject（4/10），置信度 4/5。**

问题重要，安全回收失败的 LLM LLVM-IR 优化也有清晰应用动机；然而当前稿把“现象存在”“结构化子集搜索”和“反例确实提供额外信息”捆成一个大主张。任何一层失败，论文都会退化成普通的依赖闭合 delta debugging。现有协议虽然详尽，但详尽不能替代识别性：它尚不能排除收益来自简单结构搜索、组件规模偏差、模型训练目标错配或后端计量选择。

若不修复下列 C1–C4，我会直接拒稿；其余问题会进一步把论文压到工程工具或 workshop 水平。

## 2. 可单独导致拒稿的主要问题

### C1：核心创新可能只是“把 ddmin 搬到 LLVM IR”

稿件承认部分补丁、CEGIS、依赖聚类和事务回滚均非新概念，但最强基线只有“无反例的依赖闭合 best-first”。这不足以排除：

1. 通用 ddmin/Hierarchical Delta Debugging 在相同组件图上已能得到相同结果；
2. MaxSAT/最小诊断在反例约束下比启发式队列更强；
3. LLVM SandboxIR 已提供事务保存、接受和回滚，稿件所谓“部分提交”本身不是系统贡献；
4. 反例仅改变队列顺序，核心仍是枚举编辑子集。

**必须补救：**形式化定义“精化约束编辑回收”问题；加入结构化 ddmin、反例命中集/MaxSAT 和 LLVM 事务基础设施对照；用真实反例、静态切片、打乱反例和无反例四方消融证明信息增益。若 M 不优于最强非反例结构搜索，必须删除“counterexample-guided algorithm”主张。

### C2：Alive2 反例到编辑组件的映射没有可执行契约

“从可观察差异逆向遍历”不足以复现。Alive2 的 refutation 可能涉及 poison、源/目标 UB、内存、属性或路径约束，不一定能稳定映射到目标 IR 指令，更不保证 slice 包含一个可单独回滚的责任组件。稿件既没有反例解析模式、稳定性判据，也没有无法定位时的统计分母。

**必须补救：**定义 `CE_LOCALIZABLE`、`CE_STATIC_ONLY`、`CE_UNLOCALIZABLE`；记录 witness 字段、观察差异、状态条件和组件命中；同一候选重放两次必须得到同一规范化记录；反例只能软排序，不能作 soundness 剪枝；设立反例可定位覆盖门，并把不可定位样本保留在端到端分母。

### C3：受控模型与主目标可能发生训练目标错配

主实验要求 code size，但受控 P0 直接使用 LLM-VeriOpt 的 SFT adapter。若这些 adapter 的监督数据或任务模板主要针对 latency，统一改 Prompt 并不能消除训练目标偏差。这样得到的失败候选可能只是“用错模型做错任务”，而非自然的 code-size Translator 失败。模型家族公平性无法补救任务错配。

**必须补救：**Track B 主生成改用可固定、未针对该 artifact 目标微调的 base/instruct checkpoint；artifact SFT 只进入 Track A 外部重放。若确需 SFT，必须证明训练语料和目标与 code size 对齐并单列为独立层，不能与 base/instruct 合并。

### C4：RISC-V 外部验证目前存在跨目标无效性

把为 x86 datalayout/triple 生成的 IR 直接换 triple 编译到 RV64GC，可能遇到 target intrinsic、ABI、对齐和属性差异。即便能编译，也不能代表同一源程序在 RISC-V 前端/中端流水线中的真实输入。“后端替换”还会让算法在 RISC-V 成本上重新搜索，这不是已选结果的零调参迁移。

**必须补救：**RISC-V 仅在能从同一源代码独立生成 RV64GC IR 的 D-H 程序上运行；分别定义“冻结编辑决策迁移”和“冻结算法重新搜索”；每一目标分别做 `Alive2(S_tau,R_tau)`；不能把 x86 datalayout IR 强行改 triple。D-C 不再承担 RISC-V 主验证。

## 3. 其他重大问题

### M1：搜索算法过早停在第一个 verified 盆地

当前伪代码一旦找到首个 verified 状态就跳转利润恢复，可能错过另一个保留更多有益组件的安全盆地。最终结果因此高度依赖优先队列细节，也不能合理解释 optimality gap。

**修订要求：**维护最多 `k_safe` 个非支配安全状态，继续搜索到预算耗尽或可证明的停止条件；利润恢复从安全 Pareto 前沿而不是单个状态出发。

### M2：`predicted_gain/risk` 没有冻结定义

它可以悄悄吸收目标后端、人工规则甚至实验结果，形成未声明的可调自由度。

**修订要求：**主算法只允许一个确定性、无需训练的冻结评分式；学习型或 TTI 型排序只能作为预注册变体；所有 tie-break 用稳定 ID。

### M3：对齐 precision 和依赖 recall 没有可信金标准

自然 LLM 重写没有唯一“正确对齐”，人工标注 98% recall 是伪精确。两个审计者同意也不等于覆盖了真正的语义依赖。

**修订要求：**D-U/带已知 edit provenance 的变异集用于精确恢复率；自然候选只报告可复现一致性、裁决协议和构建不变量，不声称真实语义依赖 recall。

### M4：oracle 子集存在严重选择偏差

只对 `n<=12` 的候选穷举，会系统偏向小编辑、简单 CFG 和弱模型输出。部分识别上界几乎必然过宽，不能支撑“失败候选通常可回收”。

**修订要求：**主张严格限定为 oracle-eligible 范围；对 `n>12` 运行固定预算 witness search，只能把找到的成功当保守下界，不能把未找到当失败；确认集必须复核现象而不能只复核算法。

### M5：后端代码尺寸口径可能没有真正实现 `-Oz`

`opt default<Oz>` 后接 `llc -O=3` 并不自动证明机器代码按尺寸目标生成；函数是否保留 `optsize/minsize`、目标机选项如何传递都未校准。`ST_Size` 也看不到链接松弛、ICF、常量池共享和全程序布局。

**修订要求：**在执行前用 `clang -Oz` 端到端参考管线校准抽取管线；冻结函数属性和 TargetMachine 配置；若机器码不一致则环境门失败。函数符号大小只作为机制主指标，D-H 链接后二进制大小负责外部真实性。

### M6：数据集均衡抽样不能估计自然发生率

`8 domains × 4 bins × 5` 是人为均衡设计，得到的是宏平均 benchmark estimand，不是现实项目中可回收失败的流行率。LLVM nightly 还是移动语料，12 个项目的项目级区间很脆弱。

**修订要求：**明确区分 balanced estimand 与 corpus-weighted descriptive estimate；D-C 改为 24 个项目 × 10 函数，提高项目簇数；冻结快照，任何自然分布外推都降为描述性。

### M7：统计门过度依赖任意阈值和少量项目 bootstrap

`CI lower >5%` 与 `point>=10%` 是工程决策门，不是科学真值；12 个项目上 cluster bootstrap 稳定性不足。后验 power 也容易误导。

**修订要求：**把门称为 go/no-go 工程门；D-C 至少 24 个项目；报告项目 jackknife、层级 bootstrap 和配对随机化敏感性；样本量用冻结先导参数做前瞻模拟，不用观察到的效应做“功效证明”。

### M8：LLM 在论文中的必要性尚未证明

若同样的方法对随机变异、传统错误 pass 输出或人工混合编辑同样有效，论文可能是通用 IR repair，而不是 LLM Translator 研究。仅仅让 LLM 产生输入不能自动构成 LLM 编译器贡献。

**修订要求：**加入编辑数/组件数匹配的非 LLM 负对照，比较可分解性、协同编辑比例和可回收率。论文主张应是“测量并利用 LLM whole-function translation 的混合质量结构”，而不是泛称任意优化回滚。

### M9：基线预算只给单点，容易挑预算

LLM 重试和确定性搜索的成本维度不同。一个 `128 calls/15 min` 单点可能对 SalvageIR 有利，也可能隐藏曲线交叉。

**修订要求：**主报告给 `16/32/64/128/256` 验证预算的性能剖面、AUC 和达到目标的时间；另给等 wall-clock 和等美元成本视图；任何主结论不得只来自一个预算点。

### M10：函数抽取可能改变验证语境

“单目标函数 + 必要声明”没有说明如何保留 globals、alias、comdat、函数属性和数据布局。抽取后 `Alive2(S,S)` 通过不能证明与原模块语境等价。

**修订要求：**定义 context-preserving harness；保存所有可达声明、globals 与属性；模块级编译和抽取级编译的目标函数字节需校准；跨过程和依赖无法闭合者排除并报告。

## 4. 次要问题

1. `dependency-closed component` 容易被误读为语义可独立，建议明确改称“结构可重放组件”。
2. “至少两家族为正”不能替代家族异质性区间，应报告每家族分母和最坏家族结果。
3. 相同目标 IR 去重后，统计仍按原输出计数会造成权重歧义；应同时给 candidate-cluster 与 source-level 视图。
4. `UNKNOWN` 在条件分母中排除合理，但端到端必须按未恢复处理。
5. 48 个 D-U 样例过少以覆盖 poison/undef/内存组合；至少加入属性和 datalayout 交互的组合测试。
6. 预实验已接近完整实验规模，应拆成 smoke、phenomenon、confirmation 三段，避免基础设施失败后浪费数千次生成。

## 5. 编辑部综合意见

最值得保留的核心不是“失败后回滚”，而是一个更窄、可证伪的问题：

> 对同一个被 refinement 明确反驳的 LLM whole-function IR 翻译，在结构可重放编辑格上，真实反例是否比同成本的结构搜索和安慰剂信号更快找到经直接验证且有机器码收益的严格子翻译？

只有同时满足以下三层，论文才达到强投稿线：

1. **现象层：**真实、目标一致的非 RL LLM 候选中确有可回收严格子翻译；
2. **机制层：**真实反例显著优于结构化 ddmin、无反例 best-first、静态切片和打乱反例；
3. **系统层：**在冻结后端和端到端回退口径下，收益跨项目存在，并在独立生成的 RV64GC IR 上保持方向。

任一层失败都应主动降级主张，而不是继续增加模块。
