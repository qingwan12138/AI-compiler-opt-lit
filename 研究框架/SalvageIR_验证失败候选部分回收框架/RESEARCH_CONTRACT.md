# SalvageIR 研究契约

本文件用于防止研究在实现过程中漂移。若后续要改变主对象、正确性口径或角色分类，应先显式修订本契约，而不是在实验后改写解释。

## 1. 唯一研究对象

给定源函数 `S` 与某个 LLM 生成的优化候选 `T0`，仅在以下条件全部满足时进入主任务：

1. `S` 与 `T0` 都能被锁定版本的 LLVM 解析和验证；
2. 二者函数签名和约定的可观察接口一致；
3. Alive2 对 `S -> T0` 给出明确反例，即 `REFUTED`，而不是 timeout、unsupported 或其他 unknown；
4. 变换属于预先声明的过程内支持范围；
5. `T0` 与 `S` 存在非空结构变化，而不是文本重命名或恒等复制。

主任务输出 `R`。成功必须同时满足：

```text
LLVMVerify(R) = PASS
Alive2(S, R) = VERIFIED
Cost_primary(R) < Cost_primary(S)
```

返回 `S`、仅修到与 `S` 持平、或仅比错误的 `T0` 好，都不算“有益回收”。

## 2. 核心研究问题

> 对同一个被 refinement 明确反驳的 LLM whole-function IR 翻译，在结构可重放编辑格上，真实反例能否比同成本的结构化 ddmin、无反例 best-first、MaxSAT/ILP 最小诊断和安慰剂反例，更快找到直接验证且有机器码收益的严格子翻译？

## 3. 唯一论文主张

候选主张是：

> LLVM IR 的精化语义和 SSA/CFG 依赖可以把 whole-function diff 约束成结构可重放组件空间；若真实 Alive2 反例相对打乱反例和强结构搜索具有可测信息增益，它可以在固定预算内优先找到并保留经直接验证且有收益的子翻译。

该主张当前是【候选创新】，不是实验事实。

## 4. 角色边界

- LLM 的动作是 `LLVM IR -> 优化 LLVM IR`，因此研究主体是 Translator。
- SalvageIR 是 Translator 的验证后恢复层，不选择 pass 序列，不生成可复用优化规则。
- `opt`、Alive2、后端成本和 RISC-V 测量均为 Supporting 基础设施或评价手段。
- 若未来把组件归纳成 InstCombine 规则或 LLVM pass，则形成新的 Generator 论文，不纳入本主线。

## 5. 方法边界

核心方法必须不依赖第二次 LLM 调用。核心输出由确定性的 IR 对齐、组件构造、回滚/重放搜索和验证产生。

允许设置 `SalvageIR+LocalRepair` 扩展：在核心方法结束后，让同一冻结模型只重写残余组件。但它只能作为补充结果，并单独计算模型调用和 Token 预算，不能用于支持核心算法假设。

## 6. 正确性边界

- 语义关系写作 LLVM refinement，不笼统写成数学等价。
- 最终安全性仅由整函数 `S -> R` 的直接 Alive2 结果裁决。
- 中间链 `S0 -> S1 -> ... -> R` 的逐步验证用于调试、证据记录和组合推理，但不能替代最终直接检查。
- timeout、unsupported、parser error、工具崩溃一律为 `UNKNOWN` 或工具失败。
- 测试和 fuzzing 只做补充验证，不能把“未发现反例”升级为 verified。

## 7. 主支持范围

正式主张至少覆盖：

- 单函数、过程内变换；
- 整数、位运算、比较、select、类型转换；
- 无复杂外部调用；
- loop-free 或能在固定边界内由 Alive2 处理的函数；
- 第一阶段以同 CFG 或可稳定匹配 CFG 的候选为主。

以下能力必须作为分层扩展单列：

- CFG 改写与 PHI 变化；
- 内存、别名、指针 provenance；
- 向量和浮点；
- 循环；
- 跨函数变换。

不支持的样本必须保留在覆盖率分母中，并报告排除原因。

## 8. 性能契约

主论文主要目标已经冻结：

```text
Cost_primary = 源 IR 经 default<Oz>、显式 optsize/minsize 且通过 clang -Oz 校准后，
               在固定 x86-64 generic 后端生成的目标函数 ELF 符号字节数
```

候选生成目标必须与 `Cost_primary` 一致。主要成功至少减少 `max(2 bytes, 1%)`。已有 artifact 若采用不同目标，只能用于现象先导或外部重放，不能混入主要盈利性比较。具体测量和门控遵循 [`PILOT_PROTOCOL.md`](PILOT_PROTOCOL.md)。

同时报告：

- 清理后的 LLVM IR 活跃指令数；
- x86-64 后端静态延迟或 llvm-mca 指标；
- 有可执行 harness 的子集上的实际运行时间；
- AArch64 补充结果；
- RV64GC/RVV 保留平台结果。

IR 指令数只能作为搜索代理或补充指标，不得冒充真实运行性能。

## 9. 公平性契约

对所有方法固定同一个 `(S, T0)`，并统一：

- 初始候选；
- 形式验证版本和超时；
- 最大候选次数和验证次数；
- 总墙钟时间；
- 额外 LLM 请求数、输入/输出 Token 和解码设置；
- 编译与测量流水线；
- 停止规则。

模型是分层因素，不是把所有候选混在一起的噪声。结果按模型分别报告，并使用模型宏平均和按源函数/项目聚类的置信区间。

## 10. 不可偷换的三个分母

1. **Eligible-refuted recovery rate**：只在可解析且明确 refuted 的候选上评价恢复算法。
2. **Model failure funnel**：从每个模型的全部生成结果开始，报告 format/IR invalid、refuted、unknown、verified 等比例。
3. **End-to-end useful rate**：以全部预注册源函数为分母，计算最终得到 verified 且优于源程序的比例。

三者必须同时报告，不能只报告条件恢复率。

## 11. 强制停止条件

满足任一项时，停止扩大系统：

- 跨至少三个未由本研究做任务特定训练/RL 的模型家族，明确 refuted 候选不足以构成实验；
- 结构对齐后，大多数候选只有一个不可分组件；
- 穷举小规模上几乎不存在 verified 且 profitable 的严格子集；
- SalvageIR 与 B5/B6/B7 最强结构搜索在配对比较中无可区分差异；
- 真实反例不优于同失败类别内打乱归属的安慰剂反例；
- 反例适配器稳定性不足，或动态可定位覆盖率低于 60%；
- 优势只来自更多验证调用或更多 LLM Token；
- x86-64 主结果无法在保留模型或从同源独立生成的 RV64GC IR 上复现方向；
- 真实后端收益消失，只剩 IR 指令数变化。

## 12. 完成定义

“框架完成”指研究设计齐备，不等于实验完成。进入论文实验前必须具备：

- 可复现候选清单与许可证；
- 版本锁定的 LLVM/Alive2 工具链；
- 编辑图和回滚重放器；
- 至少包含结构化 ddmin、无反例 best-first、MaxSAT/ILP 和反例安慰剂的强基线；
- 预算相等的运行器；
- 预注册统计和停止规则；
- 保留模型、保留项目和 RISC-V 外部验证队列。
