# SalvageIR v3 修订与验收记录

> salvageir_v3 · 2026-09-21。修订性质：设计/规范；不含远端实验结果。

## 1. 本轮范围与设计决策

用户授权在现有框架上持续打磨，并明确要整体复制到服务器。
接受前轮主线，不新增RL/训练、不转Selector/Generator、不以RISC-V为主要实验背景。
比较了三种路径：
- 继续只从post-Oz出发：定位清晰但候选与编辑空间受限，保留补充而非唯一入口；
- 原始O0直接生成、直接对比Oz：可以研究替代优化器，但与“补充LLVM后的回收价值”不同；
- PRE_SSA输入、统一post-Oz评价：采用为主设置，公开mem2reg与筛选边界。
主方法不承诺O0会提高可回收率；通过双设置固定源实验检验。

## 2. 已落实的修改

- 统一salvageir_v3、规范优先级、单一数值配置与单一候选状态机。
- raw→S、X→R、X→Oz(R)分别留证；自等检查不能替代规范化证明。
- 保留lifetime/noinline/语义flag；optnone仅在有前端来源证据时处理。
- 分离硬结构约束与软风险；禁止新glue；不称单个组件已独立验证。
- 改为一套回滚/加回队列与精确incumbent，删除无依据的后端“上界”。
- 反例有效性取代两次相同witness；状态内匹配随机取代跨函数错配。
- oracle四态、未知不作阴性、完整最优仅限表示空间。
- P0a缩为24个定向fixture及已有数据审计；P0b固定64源/双设置/单模型，不按失败数无限采样。
- 稀疏样本仅作可行性；正式确认用独立项目、全源端到端主终点与明确多重比较方法。
- RISC-V只要求冻结算法独立重跑；不把跨ISA掩码映射作为前置负担。
- 执行交接使用相对路径，不依赖ARIS、本地文献库或原对话。
- v2原文完整留archive/v2用于复核，不再具有执行权威。

## 3. 审稿追问后的二次修订

1. Oz可能不幂等：POST_OZ的设置内基准是P(Z)，跨设置全源比较统一C(P(S))，重复Oz纯收益单列。
2. 闭包图可能表达不了多选依赖：保留约束表达式并报告builder覆盖，不能强行把一切压成DAG。
3. 从源加回会改变搜索问题吗：仍在同一S/T0严格子集空间，公共起点对全部结构基线相同。
4. 最后证明是否“免费”：计入同一Alive2预算，预算不足不能记成功。
5. 数据不足怎么办：明确SOURCE_POOL_INSUFFICIENT，不结果驱动放宽白名单。
6. 通用修复也有效是否否定LLM定位：不否定应用价值，只删除LLM特有机制主张。
7. 服务器无代码怎么办：入口明确这是实施工单，CLI不是已存在的软件；优先适配用户已有实现。
