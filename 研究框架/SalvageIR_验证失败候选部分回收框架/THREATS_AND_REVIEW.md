# SalvageIR v3 严苛复审与风险登记

> salvageir_v3 · 2026-09-21。结论：设计可进入受限验证，研究效果未获证实。

## 1. 仍然足以拒稿的四个问题

1. 自然REFUTED候选是否有可回收且post-Oz盈利的子集？没有实证不能靠文献中的错误率替代。
2. 自动编辑空间是否系统性遗漏人工可回收方案？oracle阴性只对当前表示有效。
3. 反例是否胜过同空间强结构搜索与静态信息？不胜则反例算法贡献不成立。
4. 条件恢复率能否转化为全部源程序上的增量？强模型少失败可能让系统收益接近零。

设计文档不能回答上述问题；只能提供能否定主张的实验。

## 2. 本轮修正与残余风险

| 审稿攻击 | v3修正 | 仍需真实证据 |
|---|---|---|
| 用O0容易优化制造收益 | PRE_SSA准确命名，统一post-Oz成本；POST_OZ配对对照 | 是否仍有后端增量 |
| O0内存与无内存核心矛盾 | 明确mem2reg；残留内存单列排除 | 主池筛选损失 |
| 依赖图绑死所有编辑 | 硬结构约束与风险关系分离，flag独立 | 对齐/表示覆盖率 |
| 组件通过一次就算永远安全 | 只验证完整状态，不授予组件跨上下文正确性 | builder和日志一致性 |
| 为组合插入glue伪装严格子集 | 禁止新计算，不能接合即覆盖失败 | provenance审计 |
| 两次不同反例被误判不可靠 | 验证每个witness，解析稳定与求解多样性分开 | UB/poison适配器可靠性 |
| 错配反例安慰剂太弱 | 同一状态匹配桶内分数置换 | 实际可置换程度 |
| IR代理冒充成本上界 | 仅gain_estimate排序，真实成本裁决 | Oz后非加性与成本开销 |
| oracle有unknown还说完整 | 四态、部分识别界、表示相对最优 | 未决比例及昂贵状态 |
| P0工程要求循环依赖 | 24fixture＋现有数据先审计；自然数据不作smoke前置 | 工具可用性 |
| 95%clang字节一致虚构等价 | 明确IR管线目标，clang仅诊断 | 链接后二进制真实性 |
| 所有失败都聚在一个模型 | 全源端到端主终点，分层/保留模型 | 强模型实用性 |
| 表格精确但没统计方法 | 明确配对项目bootstrap与Bonferroni，稀疏即不确定 | 功效与确认规模 |
| AutoDL复制后无法用 | 目录相对路径、独立工单、无ARIS硬依赖 | 服务器工具/原始日志 |

## 3. 不可接受的解释

- “没有正例，所以把Oz拿掉就成功”：可以探索，但不是v3主盈利结论。
- “枚举无解，所以现实中不存在”：表示空间、工具unknown及预算仍限制结论。
- “只对小模型有效但仍普适”：必须限制适用模型和端到端收益主张。
- “加回组件只能在已验证状态扩展”：可能漏掉中间错误、组合才正确的路径，必须报告搜索限制。
- “随机变异也有效，便不是LLM编译器研究”：可作为LLM Translator的通用后处理，只不能声称LLM专有机制。
- “RISC-V上挑到几个例子，用户跨架构目标已全部达成”：存在性与总体收益分开。
- “测试通过等于形式证明”或“IR证明等于机器码证明”：均不成立。
- “框架满意等于结果满意”：本轮只验收规格自洽与可实施性。

## 4. 失败后的明确动作

| 结果 | 动作 |
|---|---|
| 来源/验证/成本链不可信 | 暂停受影响实验，修复后同样本重跑；不改成功定义 |
| 人工能回收、自动空间没有 | 优先修表示，在开发集形成新版本；保留原失败 |
| 正确子集多但Oz后无收益 | 撤回优化收益主张，判断修复工具是否仍值得投入 |
| 只找到极少自然正例 | 报存在性/成本，不自动扩到大规模，不用小样本拒绝所有可能性 |
| M≈B5/StaticOnly/MatchedRandom | 删除动态反例贡献；简单方法更适合便用简单方法 |
| M优于弱基线但不优于B6/B7 | 不声称新的搜索算法有效 |
| 独立确认无优势 | 不用开发集结果替换；收窄或停止该主张 |
| RV64GC无总体改善 | 如实报告跨后端目标未达到，不回头用RV调主算法 |

## 5. 最低人工审阅项

确认输入确有未优化出处、源级属性来源、实际模型目标与训练披露；
逐例看两端重建和硬边理由；核对最终输出hash与证明/成本hash；
检查符号/节/重定位及上下文；审阅自然反例与人工/自动结果分离；
确认测试集没有因知道恢复结果而被替换。
本次文档修订不能代替这些机器上/数据上的检查。
